# spectator-mode Delta

## MODIFIED Requirements

### Requirement: 无效玩家对象守卫

模组 MUST 对所有在线玩家枚举结果做可用性过滤：对象缺失、关键属性缺失或属性访问抛错的一律剔除。该过滤 MUST NOT 依赖玩家 tag 或白名单，以兼容第三方假人模组。过滤 MUST 复用共享的玩家守卫，模组只在本地完成守卫与自身玩家类型的绑定，MUST NOT 另立一套私有判别。

#### Scenario: 假人被跳过

- **WHEN** 世界中存在读取属性即抛错的模拟玩家对象
- **THEN** 模组跳过该对象，不读写其状态，也不因此中断 tick 循环

#### Scenario: 真实玩家不受影响

- **WHEN** 世界中同时存在真实玩家与模拟玩家
- **THEN** 真实玩家的灵魂出窍、距离监控与 HUD 均正常工作

#### Scenario: 未打标记的第三方假人也被跳过

- **WHEN** 世界中存在一个未打任何已知假人 tag 的模拟玩家
- **THEN** 模组仍将其判为不可用并跳过

#### Scenario: 守卫绑定在模组本地完成

- **WHEN** 模组消费共享守卫
- **THEN** 绑定使用模组自身解析到的玩家类型与在线枚举，不依赖共享库的玩家类型

## ADDED Requirements

### Requirement: 游戏模式读取须容错

模组 MUST 把每一次游戏模式读取视为可能抛错：读取失败时 MUST 按「无法判定」处理（命令入口拒绝执行、切换流程返回可读提示），MUST NOT 让异常穿到事件回调或命令回调外层。

#### Scenario: 假人执行旁观命令

- **WHEN** 模拟玩家执行旁观模式命令
- **THEN** 命令返回失败状态，不进入切换流程

#### Scenario: 进入旁观时位置或模式不可读

- **WHEN** 进入灵魂出窍时玩家坐标、维度或游戏模式读取抛错
- **THEN** 模组返回可读提示，不写入锚点与会话状态

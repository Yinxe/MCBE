# teleporter Delta

## ADDED Requirements

### Requirement: 假人可触发的玩家事件须在入口与推迟回调各自校验

玩家出生、重生等可被模拟玩家触发的事件，其订阅入口 MUST 校验玩家句柄可用性；凡把处理推迟到后续 tick 的，MUST 在推迟回调内部**再次**校验，因为句柄可能在推迟期间失效。校验 MUST 复用共享玩家守卫。信物发放与信物使用两条路径同样 MUST 在读取背包组件、维度与坐标时容错，读取失败 MUST 视为「本次不发/不开菜单」而非抛错。

#### Scenario: 假人召唤不产生组件读取崩溃

- **WHEN** 模拟玩家被召唤并触发玩家出生事件
- **THEN** 模组在事件入口即跳过或安全处理，不产生 `cannot read property 'getComponent' of undefined`

#### Scenario: 信物发放遇不可读背包

- **WHEN** 发放信物时玩家背包组件不可读
- **THEN** 模组静默放弃本次发放，不抛出异常

#### Scenario: 信物使用来自坏句柄

- **WHEN** 模拟玩家或失效句柄使用传送信物
- **THEN** 模组在入口与推迟回调各自校验，均不打开菜单也不抛错

#### Scenario: 推迟期间句柄失效

- **WHEN** 事件入口校验通过，但推迟回调执行时该玩家已下线
- **THEN** 回调内部重新校验并安全跳过，不向失效句柄写入，也不抛出未捕获异常

#### Scenario: 真人首次进服仍收到信物

- **WHEN** 真实玩家首次进入服务器
- **THEN** 模组在组件就绪后正常检查并发放传送信物

#### Scenario: 真人死亡重生仍收到回传对话框

- **WHEN** 真实玩家死亡后重生
- **THEN** 模组在实体就绪后正常弹出死亡回传对话框

# Spec Delta

## Purpose

区块锚定的木桶阵列存储库：把一片区域的木桶当成一个可寻址的槽位阵列，按槽位 ID 以 O(1) 存取带完整 NBT 的物品，支持动态扩容、原子传输、原位覆写、阵列巡检与丢失上报，并向多个模组共享同一份存储与常加载额度。

## ADDED Requirements

### Requirement: 存储区域注册与锚定

消费方 MUST 能以「维度 + 锚点坐标 + 可选列数」注册一个存储区域，注册后 MUST 得到一个可反复使用的区域句柄。同一锚点 MUST NOT 被注册两次。区域 MUST 锚定在固定区块坐标上，世界重载后 MUST 仍能定位到同一批木桶。

#### Scenario: 首次注册

- **WHEN** 消费方以维度 `minecraft:the_end`、锚点 `{x: 0, y: 120, z: -1024}` 注册区域
- **THEN** 返回一个区域句柄，后续存取都通过该句柄进行

#### Scenario: 重复注册同一锚点

- **WHEN** 消费方以已注册过的锚点再次注册
- **THEN** 注册被拒绝并返回明确的错误，不产生第二套木桶

#### Scenario: 世界重载后定位一致

- **WHEN** 世界卸载后重新加载，消费方用同一锚点重新注册
- **THEN** 句柄指向与重载前相同的木桶阵列，此前存入的物品仍可按原槽位 ID 读出

### Requirement: 按槽位 ID 的 O(1) 存取

`put` MUST 把物品存入阵列的一个空闲槽位并返回 `{ regionId, slotId }` 形式的引用；`read` MUST 能只凭该引用取回物品，且 MUST NOT 需要遍历阵列。阵列满时 `put` MUST 返回空值而不是抛错或静默丢弃物品。

#### Scenario: 存入并读回

- **WHEN** 消费方 `put` 一个钻石剑并拿到槽位引用，随后 `read` 该引用
- **THEN** 读回一个与存入时等价的钻石剑，物品的全部 NBT 数据保留

#### Scenario: 阵列已满

- **WHEN** 阵列没有空闲槽位时消费方 `put` 一个物品
- **THEN** `put` 返回空值，物品不被存入，阵列状态不变

#### Scenario: 取走后槽位回收

- **WHEN** 消费方 `take` 一个已存入的物品
- **THEN** 返回该物品，该槽位回到空闲状态并可被后续 `put` 复用

### Requirement: 完整 NBT 保真

存入与读回的物品 MUST 在 NBT 层面等价，包括附魔、自定义名称、Lore、耐久损耗、容器内容、成书文本与任何模组自定义标签。存储 MUST NOT 经过任何会丢失或重写 NBT 的中间格式。

#### Scenario: 带附魔与自定义名称的物品往返

- **WHEN** 存入一把带多重附魔与自定义名称的钻石剑，再读回
- **THEN** 附魔等级、附魔顺序、自定义名称与耐久完全一致

#### Scenario: 容器类物品的内容保留

- **WHEN** 存入一个内含多格物品的潜影盒，再读回
- **THEN** 盒内每一格的物品类型、数量与各自的 NBT 都与存入前一致

### Requirement: 动态扩容

当现有阵列没有空闲槽位时，存储 MUST 能自动扩容出新的木桶并继续接受 `put`，直到达到配置的容量上限。扩容 MUST NOT 改变已存在槽位 ID 的含义。

#### Scenario: 满后继续存入

- **WHEN** 阵列占满后消费方继续 `put` 新物品
- **THEN** 存储自动扩容并成功存入，先前所有槽位引用仍然有效且指向原物品

#### Scenario: 达到容量上限

- **WHEN** 扩容已达配置上限且仍无空闲槽位
- **THEN** `put` 返回空值，不再尝试扩容，也不破坏已有数据

### Requirement: 原子传输

跨区域的物品搬运 MUST 是原子的：搬运失败时源槽位 MUST 仍持有物品、目标槽位 MUST NOT 出现半份物品。消费方 MUST 能用一次调用把物品从一个区域移到另一个区域。

#### Scenario: 跨区域搬运成功

- **WHEN** 消费方把一个物品从区域 A 的槽位传输到区域 B
- **THEN** 区域 B 得到完整物品，区域 A 的原槽位变为空闲

#### Scenario: 目标区域已满

- **WHEN** 目标区域没有空闲槽位时发起传输
- **THEN** 传输失败并返回明确结果，源槽位的物品原样保留

### Requirement: 原位覆写

消费方 MUST 能用一个新物品覆写某个已占用槽位，覆写 MUST 保留槽位 ID。覆写 MUST NOT 造成物品复制或丢失。

#### Scenario: 覆写已占用槽位

- **WHEN** 消费方用新物品覆写一个已占用槽位
- **THEN** 该槽位此后读出的是新物品，槽位 ID 不变，旧物品不再可读

#### Scenario: 覆写不产生复制

- **WHEN** 覆写完成后统计阵列中的物品总数
- **THEN** 总数与覆写前一致（一个换一个），不出现两份

### Requirement: 阵列巡检与修复

存储 MUST 能巡检自身：核对记录与实际木桶是否一致，发现缺失、多余或被替换的木桶。巡检 MUST 能报告发现的问题，并 MUST 能在木桶缺失时重建它而不丢失其余槽位。

#### Scenario: 木桶被破坏后的巡检

- **WHEN** 阵列中某个木桶被玩家破坏，随后执行巡检
- **THEN** 巡检报告该木桶缺失，并重建出可用的木桶，其余槽位的物品不受影响

#### Scenario: 木桶被替换为其他方块

- **WHEN** 阵列中某个木桶被替换成石头，随后执行巡检
- **THEN** 巡检报告该位置不是预期方块，并将其恢复为木桶

### Requirement: 桶级丢失上报

当某个槽位的物品因木桶丢失或数据损坏而无法读回时，存储 MUST 触发一次丢失事件，事件 MUST 携带受影响的区域标识与槽位 ID。丢失 MUST NOT 让整个阵列不可用。

#### Scenario: 单桶丢失触发事件

- **WHEN** 某个木桶连同其中的物品一起消失，消费方尝试读取该槽位
- **THEN** 存储触发丢失事件并带上区域标识与槽位 ID，其余槽位照常可读

### Requirement: 自定义事件总线

存储 MUST 向消费方提供可订阅、可取消订阅的事件：存入、取走、移除、覆写、木桶创建、木桶恢复、物品丢失。事件负载 MUST 只含可序列化的标量，MUST NOT 携带游戏对象引用。

#### Scenario: 订阅存入事件

- **WHEN** 消费方订阅存入事件后存入一个物品
- **THEN** 收到一次事件，含区域标识、槽位 ID、物品类型 ID 与数量

#### Scenario: 取消订阅后不再收到

- **WHEN** 消费方取消订阅后再存入物品
- **THEN** 不再收到该事件

#### Scenario: 事件负载不含游戏对象

- **WHEN** 任一事件被触发
- **THEN** 负载中所有字段都是字符串或数字，可被直接序列化

### Requirement: 多模组共享存储

多个模组 MUST 能共享同一存储区域与同一份常加载额度，而不各自重复创建木桶阵列或重复申请常加载区块。共享 MUST NOT 要求模组之间互相引用。

#### Scenario: 两个模组用同一锚点

- **WHEN** 模组 A 与模组 B 先后以同一锚点注册
- **THEN** 两者拿到指向同一阵列的句柄，B 的注册不会新建第二套木桶

#### Scenario: 常加载额度不重复占用

- **WHEN** 多个模组注册同一个已加载的区域
- **THEN** 该区域对应的常加载区块只被申请一次

### Requirement: 存储命令集

库 MUST 提供一组以 `nds:` 为前缀的管理命令，用于在游戏内检查与维护存储：查看区域与槽位占用、读取指定槽位、触发巡检、执行修复。命令 MUST 只对具备管理权限的玩家可用。

#### Scenario: 查看槽位占用

- **WHEN** 管理员执行 `nds:info`
- **THEN** 输出当前区域数量、各区域槽位占用数与空闲数

#### Scenario: 非管理员执行被拒绝

- **WHEN** 无管理权限的玩家执行任一 `nds:` 命令
- **THEN** 命令被拒绝并给出权限不足提示，不产生任何存储变更

### Requirement: 作为独立库包的定位与依赖边界

本库 MUST 以 `packages/` 下的独立工作区包形式存在，版本 `0.1.21`，包名 `@mc-toolchain/nbt-data-storage`。它 MUST 只依赖官方 `@minecraft/*` 包与自身源码，MUST NOT 依赖本仓库以外的私有包（含任何 `@yinxe/*`）。它的纯逻辑部分 MUST 能在不加载游戏环境的 Node 环境下被单元测试覆盖。

#### Scenario: 依赖边界

- **WHEN** 检查本库的依赖声明与全部源文件的导入语句
- **THEN** 除官方 `@minecraft/*` 包与包内相对路径外，不存在任何外部导入

#### Scenario: 纯逻辑可离线测试

- **WHEN** 在无游戏环境的 Node 下运行本库的测试命令
- **THEN** 纯逻辑部分的用例全部执行并通过，不因缺少游戏 API 而跳过

#### Scenario: 被模组以工作区依赖引用

- **WHEN** 模组声明对本库的依赖
- **THEN** 依赖解析到仓库内的工作区包，而不是从注册表下载的同名包

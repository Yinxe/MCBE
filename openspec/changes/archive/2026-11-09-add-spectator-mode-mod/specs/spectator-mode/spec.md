# Spec Delta

## Purpose

定义「灵魂出窍 / 旁观模式」模组对玩家的可观察行为:玩家把自己切换为原生旁观者飞离真身侦查,行动范围受最大距离约束,超限进入容忍倒计时后自动回归本体,并提供管理员配置、状态持久化与重连恢复。

## ADDED Requirements

### Requirement: 切换进入旁观与回归本体

模组 MUST 提供一条所有玩家可执行的命令用于在「灵魂出窍」与「本体」之间切换。进入时 MUST 记录真身锚点(维度、坐标、进入前游戏模式)并把玩家切到原生旁观模式;回归时 MUST 把玩家传送回该锚点、还原该游戏模式并清除锚点。

#### Scenario: 首次执行进入灵魂出窍

- **WHEN** 生存模式玩家在功能启用且世界非极限模式时执行切换命令
- **THEN** 玩家被切换为旁观模式,真身位置留下标记粒子,并收到进入提示

#### Scenario: 再次执行回归本体

- **WHEN** 处于灵魂出窍状态的玩家再次执行切换命令
- **THEN** 玩家被传送回锚点坐标与锚点维度,游戏模式还原为进入前的模式,并收到回归提示

#### Scenario: 已是旁观者但无本模组锚点

- **WHEN** 玩家以旁观模式存在但玩家动态属性中没有本模组的锚点
- **THEN** 模组不改变其游戏模式,只提示这是非本模组进入的旁观状态

#### Scenario: 非玩家来源执行命令

- **WHEN** 控制台或命令方块执行该命令
- **THEN** 命令返回失败并说明该命令只能由玩家执行

### Requirement: 命令面与子命令形态

模组 MUST 只注册一条带命名空间的命令 `sp:soul`,并 MUST 以可选字符串参数承载 `menu` 子命令;MUST NOT 为此再注册第二条命令。玩家传入未知子命令时 MUST 收到用法提示且不执行任何状态变更。

#### Scenario: 子命令打开管理表单

- **WHEN** 操作员执行 `/sp:soul menu`
- **THEN** 打开管理表单,而不是切换旁观状态

#### Scenario: 未知子命令只提示用法

- **WHEN** 玩家执行 `/sp:soul foo`
- **THEN** 玩家收到用法提示,旁观状态与配置都不改变

### Requirement: 距离监控与容忍倒计时

灵魂出窍期间模组 MUST 持续测量灵魂与其锚点的三维直线距离。距离超过当前最大距离时 MUST 进入容忍阶段并开始 5 秒倒计时;容忍期内距离回到范围内 MUST 取消倒计时并恢复正常;倒计时耗尽 MUST 强制回归本体。灵魂所在维度与锚点不同时 MUST 一律按超限处理。

#### Scenario: 超限开始倒计时

- **WHEN** 灵魂与锚点的距离超过当前最大距离
- **THEN** 模组进入容忍阶段并显示剩余秒数,HUD 转为超限警示样式

#### Scenario: 回到范围内取消倒计时

- **WHEN** 容忍阶段内灵魂回到最大距离以内
- **THEN** 倒计时被取消,HUD 恢复正常样式,不触发回归

#### Scenario: 倒计时耗尽强制回归

- **WHEN** 容忍阶段持续到 5 秒倒计时耗尽
- **THEN** 玩家被强制回归本体,游戏模式与位置按锚点还原

#### Scenario: 跨维度视为超限

- **WHEN** 灵魂进入与锚点不同的维度
- **THEN** 模组按超限处理,距离显示为无穷大并进入容忍倒计时

### Requirement: 距离 HUD 呈现

灵魂出窍期间模组 MUST 在 actionBar 槽位显示距离信息,内容包括当前距离与最大距离,并按距离占比由绿到红渐变着色;容忍阶段 MUST 显示超限警示与剩余秒数。HUD MUST 通过跨行为包 HUD 仲裁总线发布,以使其它行为包能在优先级更高时接管该槽位。

#### Scenario: 范围内显示距离条

- **WHEN** 灵魂在最大距离内移动
- **THEN** actionBar 显示距离条、当前距离与最大距离,颜色随占比由绿变红

#### Scenario: 容忍阶段显示倒计时

- **WHEN** 灵魂处于容忍阶段
- **THEN** actionBar 显示超限警示条与「N 秒后强制回归」

#### Scenario: 回归后释放槽位

- **WHEN** 玩家回归本体或离线
- **THEN** 模组不再对该玩家声明 actionBar 内容,该槽位可由其它行为包接管

### Requirement: 管理员配置与持久化

模组 MUST 提供仅操作员可用的管理表单,以单个表单同时展示功能开关、最大移动距离、连线粒子开关与夜视增益开关四项,并允许一次提交保存。配置 MUST 持久化到世界,世界重启后 MUST 恢复;最大移动距离 MUST 被钳制在 5 至 400 米之间。功能被关闭时 MUST 强制所有在场灵魂回归本体。

#### Scenario: 操作员打开表单

- **WHEN** 操作员执行 `/sp:soul menu`
- **THEN** 打开的表单同时显示启用开关、最大距离滑条、连线粒子开关与夜视增益开关,并显示各自当前值

#### Scenario: 夜视增益默认开启

- **WHEN** 世界从未保存过配置,操作员打开表单
- **THEN** 夜视增益开关显示为已开启

#### Scenario: 提交后生效并持久化

- **WHEN** 操作员在表单中修改若干项并提交
- **THEN** 新配置立即生效,世界重启后仍为修改后的值

#### Scenario: 关闭功能强制回归

- **WHEN** 操作员把功能开关关闭并提交
- **THEN** 所有在场灵魂被强制回归本体,此后切换命令只返回未启用提示

#### Scenario: 最大距离越界被钳制

- **WHEN** 提交的最大移动距离小于 5 或大于 400
- **THEN** 实际生效值被钳制到 5 或 400

#### Scenario: 非操作员无法打开表单

- **WHEN** 非操作员玩家执行 `/sp:soul menu`
- **THEN** 表单不被打开,该玩家只收到无权限提示

### Requirement: 灵魂出窍期间的夜视增益与状态还原

灵魂出窍期间模组 MUST 为灵魂持续施加夜视效果,使低亮度环境下的侦查不受限。该夜视是模组赠送的效果,MUST NOT 消耗玩家自身已有的夜视时长。进入时 MUST 快照玩家原有的夜视状态(强度与总时长);回归时 MUST 按该快照**原样**恢复,剩余时长与进入那一刻相同,不扣除灵魂阶段停留的时间。进入前无夜视时回归 MUST 移除灵魂阶段的夜视。该增益 MUST 受管理员开关控制,默认开启。

灵魂阶段的模组夜视 MUST 全程不闪烁:效果剩余时长 MUST 始终高于夜视的闪烁阈值(剩余 10 秒),为此 MUST 采用显著长于该阈值的时长,并配合远早于到期的周期刷新;MUST NOT 使用短于该阈值的时长做高频刷新。

#### Scenario: 进入后获得夜视

- **WHEN** 夜视增益已开启且玩家进入灵魂出窍
- **THEN** 灵魂在灵魂阶段全程保持夜视,低亮度处视野被调亮

#### Scenario: 灵魂阶段视野不闪烁

- **WHEN** 玩家进入灵魂出窍并持续停留 1 分钟以上
- **THEN** 灵魂阶段的视野不出现夜视闪烁,夜视效果的剩余时长全程高于闪烁阈值(10 秒),即不存在「效果即将到期」的闪烁区间

#### Scenario: 原有夜视原样恢复不被消耗

- **WHEN** 进入前玩家带有剩余 3 分钟的夜视,在灵魂出窍状态停留 1 分钟后回归本体
- **THEN** 回归后该玩家仍带夜视,剩余时长仍为 3 分钟(与进入那一刻相同),强度也与进入前一致;灵魂阶段的停留时间不消耗玩家自己的夜视时长

#### Scenario: 模组夜视不叠加玩家夜视

- **WHEN** 进入前玩家带有剩余 30 秒的夜视,灵魂阶段模组施加自己的夜视
- **THEN** 回归后夜视剩余时长回到 30 秒,而不是模组施加的时长,也不叠加

#### Scenario: 原本无夜视则回归后移除

- **WHEN** 进入前玩家没有夜视,回归本体
- **THEN** 灵魂阶段的夜视被移除,玩家恢复到无夜视状态

#### Scenario: 无限时长夜视保持无限

- **WHEN** 进入前玩家的夜视时长为无限(如夜视药水效果未设上限)
- **THEN** 回归本体后夜视仍为无限时长,不被降级为有限时长

#### Scenario: 管理员关闭夜视增益

- **WHEN** 操作员在表单中关闭夜视增益并提交
- **THEN** 在场灵魂的夜视立即被移除,此后新进入的灵魂不再获得夜视,但夜视开关不影响进入与回归本体

### Requirement: 极限模式禁用

世界为极限模式时模组 MUST 拒绝进入灵魂出窍,因为该模式下的游戏模式切换是单向的;玩家加入极限模式世界时 MUST 收到功能已禁用的提示。处于灵魂出窍状态的存档在极限模式世界被加载时 MUST 退化为回归本体。

#### Scenario: 极限模式拒绝进入

- **WHEN** 玩家在极限模式世界执行切换命令
- **THEN** 玩家保持原游戏模式并收到已禁用提示

#### Scenario: 入服收到禁用提示

- **WHEN** 玩家加入极限模式世界
- **THEN** 该玩家收到功能已禁用的警告消息

#### Scenario: 极限模式下无法保持旁观

- **WHEN** 以灵魂出窍状态离线的存档在极限模式世界被加载
- **THEN** 模组按锚点把玩家回归本体,而不是恢复旁观状态

### Requirement: 灵魂状态持久化与重连恢复

灵魂锚点 MUST 只写入该玩家自身的动态属性,MUST NOT 写入世界级存储。玩家以灵魂状态离线后重连,MUST 恢复灵魂出窍会话:保持旁观模式、重建距离状态机、不移动本体,并提示可用切换命令回归。

#### Scenario: 以灵魂状态重连

- **WHEN** 玩家在上次离线时处于灵魂出窍状态,重新加入世界
- **THEN** 该玩家仍为旁观模式,距离监控与 HUD 恢复正常工作,并收到可随时回归的提示

#### Scenario: 锚点不写世界存储

- **WHEN** 检查世界级持久化数据
- **THEN** 其中不含任何玩家的灵魂锚点,只有全局配置项

#### Scenario: 重连后手动回归

- **WHEN** 已恢复灵魂出窍会话的玩家执行切换命令
- **THEN** 玩家按锚点回归本体并清除锚点

### Requirement: 旁观状态自愈

模组 MUST 周期性检查在线玩家,对「已处于旁观模式、玩家动态属性中存在锚点、但内存中无会话」的玩家重建灵魂出窍会话(或在守卫条件不满足时按锚点回归),使异常退出、事件漏触等遗留状态可恢复。

#### Scenario: 遗留旁观者被重建会话

- **WHEN** 玩家已处于旁观模式且带锚点,但模组内存中没有其会话
- **THEN** 模组重建该玩家的灵魂出窍会话,距离监控与 HUD 恢复

#### Scenario: 已是旁观者且有锚点时可直接逃逸

- **WHEN** 已是旁观模式且带锚点的玩家执行切换命令
- **THEN** 模组按锚点把该玩家回归本体

### Requirement: 无效玩家对象守卫

模组 MUST 对所有在线玩家枚举结果做可用性过滤:对象缺失、关键属性缺失或属性访问抛错的一律剔除。该过滤 MUST NOT 依赖玩家 tag 或白名单,以兼容第三方假人模组。

#### Scenario: 假人被跳过

- **WHEN** 世界中存在读取属性即抛错的模拟玩家对象
- **THEN** 模组跳过该对象,不读写其状态,也不因此中断 tick 循环

#### Scenario: 真实玩家不受影响

- **WHEN** 世界中同时存在真实玩家与模拟玩家
- **THEN** 真实玩家的灵魂出窍、距离监控与 HUD 均正常工作

### Requirement: 粒子表现

进入与回归时模组 MUST 在真身位置产生标记粒子爆发;灵魂出窍期间 MUST 在灵魂周围持续产生光环粒子、并在真身位置持续产生标记粒子。真身与灵魂之间的连线粒子 MUST 默认关闭,仅由管理员开关开启。真身所在区块未加载时 MUST 跳过真身侧粒子且不影响灵魂侧粒子。

#### Scenario: 进入时真身爆发标记

- **WHEN** 玩家进入灵魂出窍
- **THEN** 真身位置出现一次较大规模的标记粒子爆发

#### Scenario: 连线粒子默认关闭

- **WHEN** 管理员未开启连线粒子时玩家处于灵魂出窍
- **THEN** 真身与灵魂之间不渲染连线粒子,但灵魂光环与真身标记仍然可见

#### Scenario: 真身区块未加载

- **WHEN** 灵魂所在维度中真身位置所在区块未加载
- **THEN** 模组跳过真身侧粒子,灵魂侧光环继续渲染,且不抛出未捕获错误

### Requirement: 兼容下限为 Minecraft 1.21.100

模组的包清单 MUST 声明最低游戏版本 `[1, 21, 100]`,脚本模块依赖 MUST 为 `@minecraft/server [2, 1, 0]` 与 `@minecraft/server-ui [2, 0, 0]`;实现 MUST 只使用该版本可用的 Script API。`package.json` 的脚本依赖版本与包清单的 `min_engine_version` MUST 保持自洽,后者由打包从依赖版本推导。

#### Scenario: 在最低支持版本加载

- **WHEN** 在 Minecraft 1.21.100 世界的脚本环境加载该行为包
- **THEN** 行为包成功加载,自定义命令、管理表单与全部功能可用

#### Scenario: 版本声明由打包写入

- **WHEN** 执行打包
- **THEN** 包清单的版本号来自 `package.json#version`,最低游戏版本由脚本依赖版本推导

### Requirement: 纯逻辑层可脱离游戏环境测试

模组的纯逻辑部分(配置默认值与钳制、距离/容忍状态机、距离占比到颜色码的映射、HUD 文案组装)MUST 不依赖 `@minecraft/server` 与 `@minecraft/server-ui`,MUST 可单独编译并在 Node.js 下运行测试;模组 MUST 自带这些测试并可通过单一脚本命令运行。

#### Scenario: 纯逻辑测试独立运行

- **WHEN** 在模组目录执行其测试命令
- **THEN** 全部纯逻辑用例运行并通过,不加载任何游戏运行时

#### Scenario: 适配层不进纯逻辑测试

- **WHEN** 检查纯逻辑测试的编译范围
- **THEN** 只包含无 `@minecraft` 依赖的模块,持久化、粒子、表单、命令等适配层不在其中

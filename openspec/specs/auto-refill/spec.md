# auto-refill Specification

## Purpose
定义「自动替换」模组对玩家的可观察行为:在生存与冒险模式下,把主手物品的补充、挖掘工具切换、武器切换、耐久保护、不死图腾补充与挖掘防误触统一为一套自动决策,并提供管理员配置与帮助命令,且全程不使用作弊指令。

## Requirements

### Requirement: 模式与玩家守卫

模组 MUST 只对真实玩家生效，且 MUST 只在该玩家的游戏模式为生存或冒险时处理；创造、旁观模式与模拟玩家（假人）MUST 一律跳过。假人判别 MUST 以「读取游戏模式抛错、该方法缺失或返回 `undefined`」为准，MUST NOT 依赖任何模组私有 tag（第三方假人模组不保证打我们的 tag）。所有功能 MUST 受全局开关约束，全局开关关闭时 MUST NOT 执行任何自动替换。

#### Scenario: 生存模式玩家触发处理

- **WHEN** 生存模式玩家使用消耗品或攻击、挖掘
- **THEN** 模组按其功能开关执行对应的自动替换

#### Scenario: 创造模式玩家不被处理

- **WHEN** 创造模式玩家挖掉一个方块
- **THEN** 模组不切换其主手物品，也不改动背包

#### Scenario: 模拟玩家不被处理

- **WHEN** 世界中的模拟玩家（假人）产生消耗、攻击或挖掘行为
- **THEN** 模组完全跳过，不读写其背包

#### Scenario: 未打标记的第三方假人也不被处理

- **WHEN** 事件来源是一个未打任何已知假人 tag 的模拟玩家
- **THEN** 模组仍判其为假人并跳过，不依赖 tag 白名单

#### Scenario: 坏句柄来源被跳过

- **WHEN** 事件来源的玩家对象属性访问抛错
- **THEN** 模组跳过该次处理，不向外抛出异常

#### Scenario: 全局开关关闭

- **WHEN** 全局开关被关闭后玩家继续游戏
- **THEN** 消耗品补充、工具切换、武器切换、耐久保护、图腾补充与防误触均不执行

### Requirement: 消耗品自动补充

玩家使用消耗品后,模组 MUST 依据**使用后的主手状态**决定是否补货:主手为空(物品被完全消耗)时 MUST 从背包换入同 `typeId` 物品;主手为已知副作用残留(空瓶、空桶、碗)时 MUST 换入同类物品并把残留堆叠回收;主手为其它物品时 MUST NOT 做任何补货动作。

#### Scenario: 食物吃完自动补同类

- **WHEN** 生存玩家把一组食物吃到只剩最后一个并吃完,主手变为空
- **THEN** 背包中同 `typeId` 的食物被换到主手

#### Scenario: 药水留下空瓶

- **WHEN** 玩家饮用药水后主手留下玻璃瓶
- **THEN** 模组换入背包中同 `typeId` 的药水,并把玻璃瓶堆叠回背包

#### Scenario: 工具切换引起的主手变化不被撤销

- **WHEN** 工具切换已把正确工具换到主手,随后连带触发的使用事件被处理
- **THEN** 补货逻辑识别主手既非空也非副作用残留,判定与消耗无关并忽略,不把刚换上的物品换回

#### Scenario: 背包无同类物品

- **WHEN** 主手被完全消耗且背包中没有同 `typeId` 物品
- **THEN** 主手保持为空,模组不换入任何其它类型物品

### Requirement: 挖掘工具自动切换

玩家命中方块时,模组 MUST 识别该方块所需的工具类别,并据此决定是否换入更合适的工具。对没有绑定偏好的方块,模组 MUST 采取「省耐久不择优」策略:当前主手已达标时 MUST 保持不动,不主动升级为更高品质的工具。对绑定了偏好的方块,模组 MUST 按该偏好排序候选并据此决定保留或换入。

#### Scenario: 空手挖石头换入镐

- **WHEN** 生存玩家空手命中石头
- **THEN** 模组从背包换入镐到主手

#### Scenario: 已用对工具则保持不动

- **WHEN** 玩家主手已持铁镐并命中石头,背包中还有钻石镐
- **THEN** 模组不切换,继续使用铁镐

#### Scenario: 方块偏好改变选择

- **WHEN** 玩家挖掘绑定了偏好的方块(如农作物或树叶)
- **THEN** 模组按该方块的偏好排序换入更符合偏好的工具,而不是沿用省耐久的默认行为

#### Scenario: 无适用工具时保持

- **WHEN** 玩家命中某方块但背包中没有该类别的可用工具
- **THEN** 主手保持不变,模组记录一条可恢复的警告而不执行切换

### Requirement: 挖掘防误触

当挖掘工具切换本会执行时,模组 MUST 先以「玩家、主手物品、方块」为信号判断是否拦截:同一信号首次出现 MUST 拦截不切换;同一信号在窗口期(2.5 秒)内再次出现 MUST 放行并执行切换;超过窗口 MUST 视为新信号并重新拦截。该功能 MUST 可单独开关。

#### Scenario: 首次误触被拦截

- **WHEN** 玩家空手随手命中一个建筑方块,本次本会触发工具切换
- **THEN** 模组拦截切换,主手不变

#### Scenario: 窗口内再次挖掘放行

- **WHEN** 同一玩家在 2.5 秒内以相同主手物品再次命中同一方块
- **THEN** 模组确认有意挖掘并执行切换

#### Scenario: 超窗后重新拦截

- **WHEN** 同一玩家在超过 2.5 秒后再次以相同信号命中同一方块
- **THEN** 该次命中被视为首次出现,再次被拦截

#### Scenario: 拦截时给出提示

- **WHEN** 一次命中被防误触拦截
- **THEN** 该玩家在 actionbar 看到拦截提示与剩余确认秒数;确认放行后提示立即清除

#### Scenario: 关闭防误触

- **WHEN** 防误触开关被关闭后玩家首次命中本会触发切换的方块
- **THEN** 模组直接执行切换,不做拦截

### Requirement: 武器自动切换

玩家攻击实体时,模组 MUST 判断主手是否已是武器:主手已是任意武器(含弓、弩、三叉戟、重锤)时 MUST 保持不动;主手非武器或为空时 MUST 依据被攻击实体种类,按「附魔优先、其次武器类别」的两级偏好从背包换入武器。

#### Scenario: 空手攻击换入武器

- **WHEN** 生存玩家空手攻击一只僵尸
- **THEN** 模组从背包换入武器到主手

#### Scenario: 已持武器一律不动

- **WHEN** 玩家主手持弓并攻击实体
- **THEN** 模组不切换主手,尊重玩家已选定的武器

#### Scenario: 亡灵优先亡灵杀手

- **WHEN** 背包同时有亡灵杀手剑与锋利剑,玩家攻击亡灵类实体
- **THEN** 模组换入亡灵杀手剑

#### Scenario: 非亡灵优先锋利

- **WHEN** 背包同时有亡灵杀手剑与锋利剑,玩家攻击非亡灵实体
- **THEN** 模组换入锋利剑

### Requirement: 耐久保护

模组 MUST 在工具或武器被使用后检查主手剩余耐久,当剩余耐久占比低于配置阈值**或**剩余点数低于配置下限(两路取较宽者生效)时 MUST 提前把该物品收起并换入同类别中更耐久的同类候选。候选 MUST 严格更耐久;找不到合格候选时 MUST 保持不动,不得降级为更差的物品。该功能 MUST 可单独开关。

#### Scenario: 低耐久未碎即替换

- **WHEN** 玩家用一把耐久接近耗尽的镐挖掉一个方块,剩余耐久低于阈值
- **THEN** 模组把该镐换下,换入背包中同类别且更耐久的镐

#### Scenario: 绝不降级

- **WHEN** 主手工具已低耐久,但背包中同类别候选都不比它更耐久
- **THEN** 模组保持原工具不动

#### Scenario: 精准采集优先保留

- **WHEN** 被换下的旧工具带精准采集,背包中有带精准采集的同款工具
- **THEN** 模组优先换入带精准采集的同款,而非其它同类别工具

#### Scenario: 关闭耐久保护

- **WHEN** 耐久保护开关被关闭
- **THEN** 模组不再因低耐久提前替换,只在工具破碎后补同类

### Requirement: 工具破碎后补同类

玩家的工具在挖掘中破碎(使用后主手为空)时,若工具替换开关开启,模组 MUST 从背包换入同 `typeId` 的工具。

#### Scenario: 镐碎后补同类

- **WHEN** 玩家用一把镐挖掉方块后该镐破碎,背包中还有同类镐
- **THEN** 模组把同类镐换到主手

### Requirement: 不死图腾补充

当玩家的不死图腾被触发后,若图腾补充开关开启且副手已不再持有图腾,模组 MUST 从背包把备用图腾换入副手;副手仍持有图腾时 MUST 保持不动。识别图腾触发 MUST NOT 依赖某个特定版本才存在的枚举成员。

图腾触发的识别建立在 `world.afterEvents.entityHeal` 之上,该事件自 `@minecraft/server 2.6.0` 起可用。模组声明的最低依赖为 `2.1.0`,因此该事件在部分受支持的游戏版本上不存在;此时模组 MUST 通过运行时特性侦测静默跳过订阅,**MUST NOT 因此报错、崩溃或阻断其余功能**。

#### Scenario: 图腾触发后补入副手

- **WHEN** 玩家副手的图腾被消耗触发保护,背包中还有图腾,且运行环境提供 `world.afterEvents.entityHeal`
- **THEN** 模组把一枚图腾换入副手

#### Scenario: 副手仍持图腾则不动

- **WHEN** 图腾触发后副手仍持有图腾
- **THEN** 模组不覆盖副手

#### Scenario: 非图腾来源的治愈不触发

- **WHEN** 玩家因再生效果或普通治疗被治愈
- **THEN** 模组不执行图腾补充

#### Scenario: 运行环境无治愈事件时优雅降级

- **WHEN** 在 `@minecraft/server` 2.1.0 至 2.5.0 对应的游戏版本上加载模组
- **THEN** 模组正常加载,其余功能全部可用,图腾补充不生效且不报错

### Requirement: 管理员配置持久化

模组 MUST 提供仅操作员可执行的配置命令,以单个表单一次性展示全部开关与耐久保护的两个阈值,并允许一次提交保存。配置 MUST 持久化到世界,世界重启后 MUST 恢复;非玩家来源(控制台、命令方块)执行该命令 MUST 被拒绝。

#### Scenario: 操作员打开配置表单

- **WHEN** 操作员执行配置命令
- **THEN** 打开的表单同时显示全部功能开关与耐久保护的两个阈值,并显示各自当前值

#### Scenario: 提交后生效并持久化

- **WHEN** 操作员在表单中修改若干项并提交
- **THEN** 新配置立即生效,且在世界重启后仍是修改后的值

#### Scenario: 非操作员无法打开

- **WHEN** 非操作员玩家执行配置命令
- **THEN** 命令被拒绝,不打开表单

#### Scenario: 控制台来源被拒绝

- **WHEN** 从控制台或命令方块执行配置命令
- **THEN** 命令返回失败并说明该命令只能由玩家执行

### Requirement: 帮助命令

模组 MUST 提供所有玩家可用的帮助命令,列出模组的功能与机制概要。帮助命令 MUST 不依赖操作员权限。

#### Scenario: 任意玩家查看帮助

- **WHEN** 任意玩家执行帮助命令
- **THEN** 该玩家收到模组功能与机制概要

### Requirement: 不使用作弊指令

模组 MUST NOT 使用 `/replaceitem` 等作弊指令,也 MUST NOT 要求世界开启作弊;全部替换 MUST 通过背包容器与装备槽操作完成。

#### Scenario: 未开作弊的世界可用

- **WHEN** 在未开启作弊的世界中启用本模组
- **THEN** 全部自动替换功能正常生效

#### Scenario: 保留成就前提

- **WHEN** 世界未开启作弊且平台允许外部行为包保留成就
- **THEN** 启用本模组后成就仍可正常获得

### Requirement: 替换反馈音效

每次成功替换主手或副手物品后,模组 MUST 对相关玩家播放替换音效作为即时反馈;未发生替换时 MUST NOT 播放。

#### Scenario: 成功替换播放音效

- **WHEN** 模组完成一次主手或副手物品替换
- **THEN** 该玩家听到替换音效

#### Scenario: 保持不动不播放

- **WHEN** 决策结果为保持不动
- **THEN** 不播放替换音效

### Requirement: 兼容下限为 Minecraft 1.21.100

模组的包清单 MUST 声明最低游戏版本为 `[1, 21, 100]`,脚本模块依赖 MUST 为 `@minecraft/server [2, 1, 0]`;实现 MUST 只使用该版本可用的 Script API,或对高版本才存在的 API 做运行时特性侦测后优雅降级。

`package.json` 的 `@minecraft/server` 依赖版本、`manifest.json` 的 `dependencies[].version` 与 `packing.minimum_engine_version` 三者 MUST 保持自洽。

#### Scenario: 在最低支持版本加载

- **WHEN** 在 Minecraft 1.21.100 世界的脚本环境加载该行为包
- **THEN** 行为包成功加载,原生自定义命令与其余功能可用

#### Scenario: 版本声明由打包写入

- **WHEN** 执行打包
- **THEN** 包清单的最低游戏版本与版本号分别来自显式配置与 `package.json#version`

#### Scenario: 高于声明依赖的游戏提供更多 API

- **WHEN** 在提供 `@minecraft/server 2.6.0` 及以上版本的游戏上加载该行为包
- **THEN** 依赖被高版本满足,图腾补充恢复生效,无需修改包

### Requirement: 纯逻辑层可脱离游戏环境测试

模组的决策逻辑(工具评分与偏好排序、方块偏好表、实体偏好表、防误触守卫、图腾判定、瞬时破坏判定)MUST 不依赖 `@minecraft/server`,MUST 可单独编译并在 Node.js 下运行测试;模组 MUST 自带这些测试并可通过单一脚本命令运行。

#### Scenario: 纯逻辑测试独立运行

- **WHEN** 在模组目录执行其测试命令
- **THEN** 全部纯逻辑用例运行并通过,不加载任何游戏运行时

#### Scenario: 适配层不进纯逻辑测试

- **WHEN** 检查纯逻辑测试的编译范围
- **THEN** 只包含无 `@minecraft` 依赖的模块,背包、分类器、界面等适配层不在其中

# NBT 存储测试（nds-demo）

`@yinxe/nbt-data-storage`（NBT 存储基石）的游戏内演示模块：用来在游戏里**冒烟验证**库的完整能力——完整 NBT 保存、O(1) 凭据取物、动态扩容、跨模组共享、原子传输，以及**测试渠道的容量模拟**（快速堆满 + 见证扩容）。

- 打开管理菜单：`/nds-demo:ui`
- 完整配置 UI：`/nds-demo:config`（维度 / 锚点 X,Z / 底层 Y / 启用开关 / **每桶槽数** / **层数**）
- 单件存取：`/nds-demo:store`、`/nds-demo:take <格子号>`
- 批量存取：`/nds-demo:store-all`（背包物品**单页全量开关勾选，默认全选**）、`/nds-demo:take-all`（凭据勾选）
- 自检维护：`/nds-demo:check`（**损坏木桶自动重建 + 丢失槽回收**，主菜单「自检修复」同入口）
- 盘点：`/nds-demo:list`、`/nds-demo:stats`，以及库自带的 `/nds:regions`、`/nds:stats <区域ID>`

## 快速上手（游戏内）

1. 部署生成的 `nds-demo-v0.1.0.mcpack`（世界**需开启作弊**，常加载 ticking area 是 OP 命令）
2. `/nds-demo:config` 打开配置：默认末地锚点 `(0, 120, -1024)`（区块 `2:0:-64`），直接保存即可
3. `/nds-demo:ui` → 「批量存入（背包勾选）」：背包物品**一个表单全量开关勾选（默认全选，直接提交即存全部）**→ 消息里能看到**扩容见证**（新物化木桶 +N）
4. 「批量取出（勾选）」：凭据勾选 → 取出到背包，物品 NBT 完整无损

## 容量模拟（测试参数）

配置 UI 底部两个滑块（⚠️ 仅测试用途，正式模组不推荐）：

| 参数 | 范围 | 说明 |
|------|------|------|
| 每桶可用槽数 | 1..27（默认 27） | **解码恒按 27 槽/桶**（ID 语义恒定），此值只限制每桶可分配槽数——分配跳过桶内超限槽 |
| 层数 | 1..64（默认 64） | 单区域容量 = 层数 × 256 × 每桶槽数 |

调小后（如 **1 槽 × 1 层 = 容量 256 格**）：每存入一件就物化一个新木桶（扩容过程肉眼可见，消息实时汇报桶数 0→1→2…），几十次批量存入即可堆满，第 257 次提示"区域已满"。

### 层数与每桶槽数可动态调整（测试区，无需重建）

测试区域（registerTest 创建，带 test 标记）随时可改：

- **层数滑块**：扩层任意生效（继续存自动向新层长桶）；缩层需被裁掉的高层没有物品（有则提示先取出）
- **每桶槽数滑块 0..27**：任意调整——缩小后已占用的超限槽保留可读可取，只是不再分配；调成 **0** = 容量 0，put 全部拒绝，**直接见证"阵列瞬满"**；调大则继续扩容
- 每次调整后自动**重扫全部容器重建空洞池**（对齐世界真值，清除遗留洞）；已存物品的 ID 在任何参数下都按 27 槽/桶解码，永不偏移
- 正式区域（无 test 标记）参数不一致仍会被拒绝并提示换锚点——测试参数只作用于测试区域

### ID 安全（为什么调整容量不会弄丢旧数据）

- **ID 语义恒定**：slotId 永远按 27 槽/桶解码。即使把每桶槽数从 27 改成 1，ID=2 依然指向"桶0槽2"——曾存过的物品随时可读可取，不会偏移/错读/变孤儿。
- **同区块改布局会被拒绝**：把已注册区块的每桶槽数/层数改掉再保存 → 提示「该区块已被布局(每桶N槽/层数M)占用，测试区域请更换锚点」。**换锚点 = 开新区块 = 全新 ID 空间**，旧区域数据原样保留，把配置改回去即可继续存取旧物品（凭据列表按区域自动过滤）。
- 记录里持久化着每块区域的布局，解码永远按各自记录走。

## 配置说明

| 配置项 | 说明 |
|--------|------|
| 启用存储 | 关闭后停止存取；已存物品保留在桶阵列中，重新启用即可继续 |
| 维度 | 末地（推荐，避免干扰主世界）/ 主世界 / 下界 |
| 锚点 X / Z | 任意整数坐标，**所在区块**（`floor(x/16)`）即存储地址；同区块共享同一阵列 |
| 底层 Y | 最底层木桶的高度（-64..256，默认 120） |

## 存储原理（一句话）

物品以完整 `ItemStack` 存入"锚点区块的物理木桶阵列"（按使用逐桶物化，y=120 起向上堆）。`put` 返回 `{regionId, slotId}` 凭据，之后按格子号 O(1) 秒取。存的东西可以去末地锚点区块上方亲眼看到——桶就摆在那里，还能用普通容器交互方式翻看。

> 详细原理（寻址/空洞/并发/常加载/键约定）见 `@yinxe/nbt-data-storage` 与 `demo/AGENTS.md`。

## 防丢物保障

- 取出时背包放不下 → 剩余部分自动放回存储并提示新槽位，**物品不丢不重复**
- 存入成功才清空源槽，不会凭空复制物品
- 注册/读写全程 try-catch：区块没加载、作弊没开、布局冲突等异常情况降级为提示，不崩溃

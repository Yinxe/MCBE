# 资源回收（reclaim）功能流程

> 一句话:把假人持有的物品与经验（在线取实体真值、离线取物品仓快照）按勾选交还给真实玩家，防止假人下线或删除后财物两空。

> 假人物品与经验交还给真实玩家的完整管线。文中「文件相对路径 + 函数/类/常量名」均对应 `scripts/` 下当前实现，逐条与代码行为核对（基线：分支 `feat/mock-player-rewrite`，2026-09-29，含"九开关 + 交付目标在线前置"改版）。

## 0. 概念与命名澄清

| 术语                      | 指代                                                                                                                              | 位置                                                                                                                                             |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| 回收（reclaim）           | 假人持有的物品/经验 → 交付操作者                                                                                                  | `Lifecycle.reclaim` / `EntityOps.reclaimFrom*`                                                                                                   |
| 物品仓（ItemVault）       | 假人离线时的 NBT 木桶阵列存档（`mockplayer:test` 维度锚点 (16,0,16)，空槽用 `structure_void` 占位保绑定；`takeAll` 仅删除时发生） | `engine/ItemVault.ts` 文件头纪律注释 + `STORAGE_REGION` / `PLACEHOLDER_TYPE` 常量                                                                |
| 宝库（Vault 能力）        | 假人的工作设施（chest 交互），与物品仓无关                                                                                        | `application/Capabilities/Vault.ts`                                                                                                              |
| 滞留导出（pendingExport） | 仓区块未加载时的实体态内存快照，由 Scheduler 周期补写                                                                             | `engine/EntityOps.ts` 的 `PendingExport` 接口与 `EntityOps.drainPendingExports()`、`application/Scheduler.ts` 的 `Scheduler.tick()` 滞留补写分支 |

注意：面板标题"回收资源"、命令 `mp:reclaim`、删除路径的"回收自"私信共用一套交付原语，但走三个不同入口（见 §1）。

## 1. 三个入口

```
假人面板 →「回收资源」按钮 ──→ showReclaimForm（九开关多选，选择性回收）
/mp:reclaim <假人名>        ──→ lifecycle.reclaim(viewer, botId)（sel 缺省 = FULL_RECLAIM 全量）
/mp:remove（删除路径）      ──→ lifecycle.remove → doDelete → deliverVaultToPlayer（仓 takeAll，独立原语）
```

- 面板按钮：`interface/Panels/BotPanel.ts` 中 `showBotPanel()` 的「回收资源」按钮 → `interface/Panels/Reclaim.ts` 的 `showReclaimForm()`。**面板不要求假人在线**（离线也可开，预览走仓快照）。
- 命令：`interface/Commands.Lifecycle.ts` 的 `LIFECYCLE_COMMANDS` 中 `mp:reclaim` 项，不传 `sel`，EntityOps 侧默认参数取 `FULL_RECLAIM`（`engine/EntityOps.ts` 的 `FULL_RECLAIM` 常量，九开关全 true）。
- 删除：`application/Lifecycle.ts` 的 `Lifecycle.remove()`——在线先走下线管线（`Lifecycle.doOffline()` 里 `exportItems`+`captureExperience` 落仓落记录），再 `Lifecycle.doDelete()`。

## 2. 选择模型（九开关，互不重叠可多选）

`ReclaimSelection`（`engine/EntityOps.ts` 的 `ReclaimSelection` 接口）为扁平九布尔：

| 开关                                   | 覆盖面     | 在线口径                        | 离线/死亡口径                        |
| -------------------------------------- | ---------- | ------------------------------- | ------------------------------------ |
| `xp`                                   | 经验       | 实体真值（level+进度换算总 XP） | 记录快照 `record.experience.totalXp` |
| `hotbar`                               | 热栏 0-8   | **除选中格外**的 8 格           | 除 slot0 外的 1-8                    |
| `inventory`                            | 背包 27 格 | 9-35                            | 9-35                                 |
| `mainhand`                             | 主手 1 格  | `selectedSlotIndex`             | **slot0 约定**（与预览同口径）       |
| `offhand`/`head`/`chest`/`legs`/`feet` | 装备 5 位  | `minecraft:equippable`          | 仓 equip 五槽                        |

`hotbar + mainhand + inventory` 恰划分 36 格（归属判定 `slotWanted`，`engine/EntityOps.ts` 的 `slotWanted()`），装备五位独立——九个开关任意组合无重叠、无遗漏。

## 3. 权限、身份与交付目标前置

- 统一过 `canManage`（`domain/Permissions.ts` 的 `canManage()`）：管理员放行；否则要求 `record.ownerKey !== null && ownerKey === viewer.key`——**无主假人仅管理员可回收**。
- 面板侧 Viewer 由 `uiViewer(player)` 构造（`interface/Kit.ts` 的 `uiViewer()`）：`key = playerKey(player.name)`、`isOp = 权限等级 ≥ 2`。`playerKey` 当前恒等于玩家名（无 XUID 暴露，`domain/Identity.ts` 的 `playerKey()`）。
- **交付目标在线前置（改版新增）**：任务体执行时先查 `ops.isOnlinePlayer(viewer.key)`，操作者此刻已离线则整单改期 `{ ok:false, reason:"交付目标已离线，回收未执行" }`（`application/Lifecycle.ts` 的 `Lifecycle.reclaim()` 邮箱任务体首行）——杜绝排队期间掉线导致"已摘除却无人可交付"的丢物窗口（摘除/回写均发生在该检查之后，未通过即一物不动）。

## 4. 主编排：`Lifecycle.reclaim`（`application/Lifecycle.ts` 的 `Lifecycle.reclaim()`）

```
reclaim(viewer, botId, sel?)
 ├─ 记录不存在 → { ok:false, "假人不存在" }            （同步早退，不进邮箱）
 ├─ canManage 不过 → { ok:false, "只有主人或管理员可回收该假人" }
 └─ mailbox.post(botId, "reclaim", 任务体)
     ├─ 操作者离线 → { ok:false, "交付目标已离线，回收未执行" }（isOnlinePlayer 前置）
     ├─ live = stateFlags(st).online && !death
     ├─ !live 且 !vaultReadable(botId)
     │    → { ok:false, "物品仓区块未加载（世界尚未就绪），请稍后再回收" }（缺53）
     ├─ live  → ops.reclaimFromEntity(viewer.key, botId, sel)
     ├─ !live → ops.reclaimFromVault(viewer.key, botId, rec.experience, sel)
     ├─ 返回 null（实体不可达）→ { ok:false, "无法在世界中找到该模拟玩家" }（绝不静默改走仓）
     ├─ if (!sel || sel.xp) → rec.experience 归零 + saveGate.saveRecord（xp 归零分支）
     └─ { ok:true, ...counts }
```

要点（均为代码事实）：

1. **串行化**：任务经 Mailbox（`application/Mailbox.ts` 的 `Mailbox.post()`），同一 botId 至多 1 执行 + 1 排队，与 online/offline/delete 等管线互斥——注释口径"防 exportItems 竞态双发"。同标签重复投递合并返回既有 Promise；异标签会**替换排队位**，被替换的旧任务 resolve `null`，reclaim 侧映射为 `{ ok:false, reason:"意图被替换或管线内部异常" }`（`Lifecycle.reclaim()` 尾 `.then` 兜底分支）。
2. **死亡也算仓路**：`live` 判据排除 death；死亡窗口内 `handleDeath` 已 `exportItems` 快照"有什么存什么"（`Lifecycle.handleDeath()`），所以死亡回收读到的是死亡时刻的仓态。
3. **经验记录只在勾选 xp（或全量缺省）时归零**——部分回收不动经验，杜绝"没勾也被清"（`Lifecycle.reclaim()` 的 xp 归零分支）。
4. 回执形状 `ReclaimOutcome = { ok:true } & ReclaimCounts | { ok:false, reason }`，`counts = { items, overflow, xp, xpLevel }`（按堆计数；`engine/EntityOps.ts` 的 `ReclaimCounts` 接口、`application/types.ts` 的 `ReclaimOutcome` 类型）。

## 5. 在线回收：`EntityOps.reclaimFromEntity`（`engine/EntityOps.ts` 的 `EntityOps.reclaimFromEntity()`）

实体真值路线，逐格**先摘除后收集**——任何一格 `setItem(i, undefined)` 抛错则该格跳过，物品留在实体上（"比复制安全"，`reclaimFromEntity()` 内 `setItem` try/catch 分支）。

1. 主手 = `bot.selectedSlotIndex`（不可读时回退 slot0，`reclaimFromEntity()` 内 handSlot 初始化段）；遍历 36 格按 `slotWanted`（选中格→`mainhand`、其余 0-8→`hotbar`、9-35→`inventory`）勾选摘除。
2. 装备 5 位按 `sel.head/chest/legs/feet/offhand` 从 `minecraft:equippable` 摘除，同样先摘后收。
3. 经验（勾选时）：`xpLevel = bot.level`、`xp = totalXpForLevel(xpLevel) + bot.xpEarnedAtCurrentLevel`（`domain/XpMath.ts` 的 `totalXpForLevel()`，MC 分段升级公式；读经验异常按 0，物品照常交付）。
4. `giveToPlayer(viewer.key, items, xp)` 交付（见 §7）。
5. `xp > 0` 时 `clearExperience(botId)`：首选 `runCommand("xp -2147483647L")`；抛错才兜底 `resetLevel()` / `addLevels/addExperience` 负补——引擎实测 `addExperience(-n)` 对假人不生效（`engine/EntityOps.ts` 的 `EntityOps.clearExperience()`）。
6. **`exportItems(botId)` 现态回写仓**（`reclaimFromEntity()` 尾段）：摘除后的实体态必须落仓，否则下次上线 `importItems` 还原旧物 = 刷物。区块未加载时转滞留快照（§8）。
7. 返回 counts；`items`/`overflow` 来自交付结果。

## 6. 离线/死亡回收：`EntityOps.reclaimFromVault`（`engine/EntityOps.ts` 的 `EntityOps.reclaimFromVault()`）

仓快照路线，无实体参与：

1. 前置可信门（在 Lifecycle 里，§4 之 2）：`vaultReadable = permitVaultTrust(有滞留导出?, 有绑定槽?, 阵列区块已加载?)`（`engine/EntityOps.ts` 的 `EntityOps.vaultReadable()`、`domain/SavePolicy.ts` 的 `permitVaultTrust()`）——有未落仓滞留导出即"仓态落后实体"，读旧仓交付+写回失败=同物双发，一律改期。
2. 主手 = **slot0 约定**（`reclaimFromVault()` 内 `slotWanted(sel, i, 0)` 判定）：主手开关取 slot0、热栏取 1-8、背包取 9-35——与面板预览口径一致（改版将预览"首个非空"统一为 slot0）。
3. `readInventory/readEquipment` 逐格判 `sel`，命中收集并记 `taken[i]`。
4. `xp = sel.xp ? recordXp.totalXp : 0`——经验取**记录快照**（离线无实体真值）。
5. `giveToPlayer` 交付后，**仅把被取走的格回写为 null**（`saveInventory/saveEquipment`），未勾格原样保留——"选择性回收只勾走的部分回写仓，未勾动一格"（`reclaimFromVault()` 尾段回写；绑定保留，takeAll 是删除专用）。
6. `xpLevel` 仅在勾选 xp 时回 `recordXp.level`，否则 0。

## 7. 交付：`EntityOps.giveToPlayer`（`engine/EntityOps.ts` 的 `EntityOps.giveToPlayer()`）

- 按名找真人；找不到 → 全零返回（不抛）。回收链路已前置在线检查（§3），此处兜底语义不变。
- 逐堆 `container.addItem(item)`；返回 remainder 或抛错 → `dimension.spawnItem(remainder, player.location)` 在玩家脚边落地（保 NBT），`overflow` 只计有剩余的堆；`items` 按堆计数（无论是否溢出）。
- `totalXp > 0` 时 `player.addExperience(totalXp)`，异常忽略——**经验只增不减**。
- 落地溢出物可被玩家/假人拾取，属于交付失败兜底而非销毁路径。

## 8. 滞留导出闭环（防丢物）

```
exportItems 时区块未加载 → pendingExports.set(botId, 快照)      （EntityOps.exportItems 内区块未就绪分支）
Scheduler 每 PENDING_EXPORT_RETRY_TICKS 探测并 drainPendingExports（Scheduler.tick 内滞留补写分支）
上线 importItems / 回收改期判定 / 删除交付 各自前置处理滞留      （EntityOps 的 importItems / vaultReadable / deliverVaultToPlayer）
```

- 删除路径 `deliverVaultToPlayer`（`engine/EntityOps.ts` 的 `EntityOps.deliverVaultToPlayer()`）：`takeAll` 取仓并销绑定表；**若有滞留快照，用快照取代仓内旧副本交付**（快照=实体最后全量态，否则同物双发），随后删快照。
- 管理面板诊断：区块状态 + `pendingExportList()` 滞留件数（`interface/Commands.Admin.ts` 的 `ADMIN_COMMANDS` 中 `mp:storage` 项）。

## 9. 面板预览与交互（`interface/Panels/Reclaim.ts`）

1. `buildPreview`：`botStatus`（会话态优先、`record.deathMark` 兜底，`interface/Kit.ts` 的 `botStatus()`）判 live。
   - live：经验取实体真值（`captureExperience` 失败回退记录）；`panelOps.liveSlots`——主手=选中槽，热栏=0-8 中除选中槽，背包=9-35。
   - 非 live：`panelOps.vaultSlots` 仓快照；主手=slot0，热栏=1-8，背包=9-35（与执行同源）。
   - `xp` 仅 `totalXp > 0` 才显示数值。
2. 表单九开关（顺序即覆盖面序），每项上方一行预览（单项 `sectionLabel` 物品摘要、成组 `groupLabel` 走 `invSummary` 前 3 种×数量）：
   `回收经验` / `回收热栏(无主手)` / `回收背包(27)`（**唯一默认勾选**）/ `主手` / `副手` / `头盔` / `胸甲` / `裤腿` / `靴子`——任意多选，互不重叠。
3. 提交：组扁平 `ReclaimSelection` → `system.run(async …)` 调 `lifecycle.reclaim(viewer, botId, sel)`，结果再回 `system.run` 播报：
   - 失败：`回收失败: <reason>`；
   - 成功按 `items/overflow/xp(Lv)` 拼明细；全零 → `背包是空的`。

## 10. 失败与边界一览（与代码逐条对应）

| 场景                               | 行为                                       | 出处                                                   |
| ---------------------------------- | ------------------------------------------ | ------------------------------------------------------ |
| 假人记录不存在                     | 早退 `假人不存在`（不入邮箱）              | `Lifecycle.reclaim()` 记录缺失早退                     |
| 非主人且非管理员 / 无主假人        | `只有主人或管理员可回收该假人`             | `Lifecycle.reclaim()` canManage 拒绝段                 |
| **执行时操作者已离线**             | **整单改期，一物不动**                     | `Lifecycle.reclaim()` 邮箱任务体 isOnlinePlayer 前置   |
| 离线 + 阵列区块未加载 / 有滞留导出 | 改期，提示"请稍后再回收"                   | `Lifecycle.reclaim()` vaultReadable 判定段             |
| 在线但实体不可达                   | `无法在世界中找到该模拟玩家`，**不回落仓** | `Lifecycle.reclaim()` counts null 分支                 |
| 排队位被新意图替换                 | `意图被替换或管线内部异常`                 | `Lifecycle.reclaim()` 尾 `.then` 兜底分支              |
| 单格摘除抛错                       | 该格跳过，物品留在实体（宁漏不 dup）       | `EntityOps.reclaimFromEntity()` setItem try/catch 分支 |
| 实体经验清零抛错                   | 记录侧强制归零杜绝重复回收                 | `Lifecycle.reclaim()` xp 归零分支                      |
| 玩家背包满                         | 溢出堆落玩家脚边，计入 `overflow`          | `EntityOps.giveToPlayer()` remainder 落地分支          |
| 操作者已离线（删除路径私信）       | 回收仍执行，提示静默丢弃                   | `EntityOps.notifyPlayer()` 离线静默分支                |

## 11. 时序图（在线全量回收）

```mermaid
sequenceDiagram
    participant U as 操作者(命令/面板)
    participant I as interface
    participant L as Lifecycle(application)
    participant M as Mailbox
    participant E as EntityOps(engine)
    participant V as ItemVault(仓)
    U->>I: /mp:reclaim 名 或 勾选提交
    I->>L: reclaim(viewer, botId, sel?)
    L->>L: 存在性 + canManage
    L->>M: post(botId,"reclaim",task)
    M->>E: 操作者在线校验
    M->>E: live → reclaimFromEntity(viewer.key,…)
    E->>E: 逐格摘除(主手/热栏/背包/装备) + 读经验真值
    E->>U: giveToPlayer(入包/溢出落地/addExperience)
    E->>E: clearExperience(实体)
    E->>V: exportItems(现态回写仓; 区块未载→滞留快照)
    L->>L: sel.xp 或缺省 → 记录经验归零 saveRecord
    L-->>I: ReclaimOutcome{items,overflow,xp,xpLevel}
    I->>U: 播报明细 / 失败原因
```

# 传送（teleporter）

单人/多人传送管理：传送点、死亡点、玩家间传送请求。无需开启作弊，保留成就。

- 包名：`@mc-toolchain/teleporter`
- 版本：`0.0.6`（沿用上游版本号，见 design D3）
- 最低游戏版本：`1.21.120`
- 脚本 API 依赖：`@minecraft/server 2.3.0`、`@minecraft/server-ui 2.0.0`

## 功能

- **传送点**：在当前位置创建、分类（家/资源点/生电/遗迹/群系/其他）、备注、置顶、更新坐标、删除；自动记录群系中文名
- **公共传送点**：把传送点设为公开，所有玩家可见可传送，标注所有者与传送次数
- **死亡点**：死亡自动记录（每人保留最近 10 条），`/tpa:back` 一键回传，重生时可选择立即回传
- **玩家间传送**：`/tpa:tpa` 请求传送、`/tpa:tphere` 请求对方过来，60 秒有效，需对方接受
- **传送信物**：磁石指针（`minecraft:lodestone_compass`），右键打开主菜单；死亡不掉落、锁在背包内；首次进入自动发放
- **GTA 风格传送转场**：移植自上游 Fabric 模组 `GrandTeleport`。相机脱离玩家升到高空、俯视横越世界、再落回落点视角；默认开启，可全局关闭或换成淡入淡出

## 命令

全部命令由玩家执行；控制台与命令方块执行会返回失败（见「已知约束」）。

| 命令 | 说明 | 参数 |
| --- | --- | --- |
| `/tpa:menu` | 打开传送管理菜单 | — |

## 传送转场

移植自上游 Fabric 客户端模组 `GrandTeleport`（MC 26.2）的运镜，只保留基岩版能复刻的部分。

### 运镜时序

一次同维度传送由 9 个阶段组成（单位 tick，20 tick = 1 秒）：

| 阶段 | 时长 | 内容 |
| --- | --- | --- |
| 出体 | 12 | 相机从眼睛升到脚上方 6 格，视角转向 90° 正俯视 |
| 出体悬停 | 10 | 再滑出 0.5 格 |
| 拉远三段 | 13 + 13 + 13 | 高度依次经过 20 / 40 / 60 格 |
| 等待 | 10 | 锁在 60 格 |
| 横越 | 20–60 | 按水平距离折算（30 格/tick），两端平滑起停 |
| 等待 | 10 | 锁在落点上方 60 格 |
| 推近三段 | 13 + 13 + 13 | 高度依次经过 60 / 40 / 20 格 |
| 入体悬停 | 10 | 再收回 0.5 格 |
| 入体 | 12 | 从脚上方 6 格降回落点眼睛，视角转回玩家朝向 |

变焦与横越阶段叠加双正弦微抖：俯仰只向俯视方向单侧偏移（不会朝天），偏航双向摆动小于 1°。

### 转场是位移的包裹层

**玩家位置在横越阶段才真正提交**，不是先瞬移再补动画。因此出体、悬停、拉远与等待这几十个
tick 天然成为落点区块的加载窗口——运镜开始时还会用临时 ticking area 主动预加载落点周边
3×3 区块，转场结束即释放。预加载失败只记日志，不影响传送。

### 配置项

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `transitionEnabled` | `true` | 转场总开关。关闭等价于风格为 `off` |
| `transitionStyle` | `"cinematic"` | `off` / `fade` / `cinematic` |
| `transitionZoomHeights` | `{ overworld: [20,40,60], nether: [20,40,60], end: [20,40,60] }` | 三段变焦高度，按维度划分 |
| `transitionZoomTicks` | `[13, 13, 13]` | 三段变焦时长，不分维度 |
| `transitionVolume` | `0.5` | 转场音效音量，0–1 |

全部为新增字段并带默认值，老存档升级后自动获得电影感转场，无需迁移。

**怎么改**：

- 主菜单 → **✦ 传送转场**：所有玩家都能进。可开关转场、选风格、调音量。
- 同一界面的下半部分（仅 OP / `op` 标签可见）：按维度调整三段变焦高度与时长。
- `/tpa:config`：以文本形式查看当前配置（含「传送转场」一行）。

> 为什么开关不藏在「管理设置」里：转场默认开启，每个玩家一传送就会看到运镜。
> 如果只有 OP 能找到开关，普通玩家既不知道有这功能、也无法在自己不想要时关掉。

### 与上游的差异

| 上游能力 | 本模组 | 原因 |
| --- | --- | --- |
| 自定义音效（`gtalike_teleport:*`） | 不移植，只用原版音效 | 上游音效素材为 ZapSplat 付费授权，不可随 MIT 代码分发 |
| Voxy / Distant Horizons / Bobby 远景地形兼容 | 不移植 | 基岩版无对应能力；用 ticking area 预加载缓解 |
| 区块逐块淡入（地形回退模式） | 不移植 | 基岩版脚本 API 无法逐块控制地形渲染 |
| HUD 淡出、隐藏本地玩家模型 | 不移植 | 切到自由相机后玩家模型本就不可见；`hideGui` 无脚本 API |
| 传送来源嗅探（`/tp`、JourneyMap、Waystones 等） | 不需要 | 本模组的传送入口是封闭且自有的 |
| 跨维度相机横越 | 降档为黑屏淡入淡出 | 相机无法随玩家跨维度存续 |

## 目录分层

```
scripts/
├── core/       纯逻辑:类型、配置归一化、传送点、死亡点、请求簿、命名映射、信物判定、
│               转场时序与相机位姿。不 import @minecraft/*,可被 node --test 直接覆盖
├── mc/         适配层:唯一接触 @minecraft 的地方
│   ├── ui/     本模组的 7 个屏幕(与共享包 packages/mod-common 不是同一层)
│   └── ...     存档、探测、传送、转场驱动、位移原语、信物、请求、事件、命令、业务动作
├── version.ts  日志版本号常量
└── main.ts     组合根:startup 阶段一次性注册命令与事件
```

`core/` 依赖 `mc/` 是禁止的;`mc/` 可以依赖 `core/`。`tests/tsconfig.json` 的 `include`
只含 `core/` 与 `tests/`,因此 `@minecraft` 一旦泄漏进 `core/` 会立刻编译失败。

界面与表单来自共享包 [`@mc-toolchain/mod-common`](../../packages/mod-common/README.md);存档键名与
JSON 载荷沿用上游，老存档可直接升级。

## 已知约束与取舍

- **命令只能由玩家执行**：所有命令在控制台与命令方块中返回失败。原因是界面、传送、
  存档写入都依赖玩家上下文。
- **命令回调不直接干活**：命令回调运行在受限上下文（read-only mode），传送、打开界面、
  写存档都会抛 `cannot be called in read-only mode`。回调体只做参数解包、来源校验与鉴权，
  其余全部交给 `@mc-toolchain/mod-common` 的执行助手推迟到安全 tick。机制与判定标准见
  [`docs/research/read-only-context.md`](../../docs/research/read-only-context.md)。
- **玩家传送可无同意移动他人**：`/tpa:menu` → 玩家传送 → 「让他传送过来」会把对方拉过来
  而无需对方同意。与上游行为一致，属「全量对齐」的已知取舍；需要征得同意请用 `/tpa:tpa`。
- **公共传送点索引只增不减**：`teleporter:players` 索引记录过所有写数据的玩家 ID，
  玩家离开后不会清理。数据量极小（每 ID 约 36 字节），暂不处理。
- **传送计数在成功后才累加**：命令与界面两条入口都先确认传送成功再计次，避免失败也涨次数
  （上游公共传送点界面存在先计次后传送的问题，此处已修正）。
- **转场把「传送成功」的判定时点后移**：带转场时位置在横越阶段才提交，成功提示在运镜结束后
  才发出。这是有意的：期间玩家看到的是正在播放的运镜，输入已被冻结，不会误操作。关闭转场后
  行为与旧版完全一致。
- **转场期间冻结输入**：运镜期间关掉移动与相机输入权限，结束、被新传送接管、玩家离线或死亡
  时恢复。异常未正常结束时由超时兜底强制恢复，玩家不会卡在原地。
- **信物从纸改为磁石指针**：识别依据是「物品类型 + 描述行」，旧版发出的纸信物已失效。
  玩家首次进入或执行 `/tpa:token` 时，模组会清掉背包里的旧纸信物并补发磁石指针，
  不需要手动处理。

## 开发

```bash
npm run lint          # eslint + prettier + minecraft-linting
npx tsc -p tsconfig.json --noEmit
npm test              # 编译并运行 core 层单元测试
npm run verify:transition  # 用 mock 的脚本 API 驱动转场适配层(证明相机真的被驱动)
npm run pack          # 生成 .mcpack 到仓库根的 release/
npm run generate:icon # 重新生成 128×128 pack_icon.png
npm run local-deploy  # 部署到本地 Minecraft
```

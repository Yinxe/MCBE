# 侧载行为包与成就(MCPE-242529)

这是本模组最关键的**外部约束**:它能决定「这个模组到底能不能用」。

## 1. 结论

**Minecraft 基岩版 1.26.50 起,激活侧载(sideloaded,即非 Marketplace 渠道)的行为包会禁用该世界的成就。**

- 该行为是平台级 bug:**MCPE-242529**
- 在此之前,`manifest.json` 的 `metadata.product_type: "addon"` 可以让侧载附加包不被判定为「作弊」,从而保留成就
- 1.26.50 起这条豁免失效,即使正确标注 `product_type: "addon"` 也会禁成就

因此本模组的「可获得成就」区间是:

| 游戏版本 | 成就 |
| --- | --- |
| 1.21.90 – 1.26.40 | 可获得(需关闭作弊) |
| 1.26.50 及以上 | 不可获得(平台 bug,非本模组能规避) |

> 用户曾提到「1.26.50 禁用是已上报的 bug,可能被修复」。如果官方修复,上限会重新打开;因此文档只把 1.26.40 写成**当时实测的上限**,而不是永久上限。

## 2. 由此产生的实现约束

这个约束直接决定了几处设计:

1. **绝对不能调用 `world.gameRules.commandBlocksEnabled = true` 或任何「开启作弊」类设置。**
   参考实现(`~/coding/MCBE/mcaddon/keepinventory`)里有这一句,但在这里必须删掉——它会直接让世界变成作弊世界,成就永久失效。

2. **只改 `keepInventory` 一个游戏规则。**
   `keepInventory` 本身不触发「作弊」判定(它是世界设置,不是命令),所以「死亡不掉落」可以用不破坏成就的方式实现。这也是本模组选择 `gameRules` 而不是「监听死亡事件再手动把物品塞回背包」的原因——后者在 1.26.50+ 同样救不了成就,还更复杂。

3. **`manifest.json` 仍标注 `metadata.product_type: "addon"`。**
   虽然 1.26.50+ 不再豁免,但在 1.26.40 及以下它仍是必要的;保留它没有坏处。

## 3. 实测观察

- `mct validate` 对 `metadata.product_type: "addon"` 无告警,说明它是合法字段。
- 参考实现把 `@minecraft/server` 定到 `[2, 5, 0]`,同时开启 `commandBlocksEnabled`;本模组刻意不跟随这两点。
- 成就状态**无法在无头环境验证**,必须在真实客户端观察。这是 `tasks.md` 中 4.2 被标记为「需用户实机验证」的原因。

## 4. 需要用户实机验证的内容

| 场景 | 期望 |
| --- | --- |
| MC 1.21.90 + 最新版,关闭作弊,死亡一次 | 物品与经验保留 |
| MC 1.26.40 及以下,关闭作弊,新世界 | 成就可正常解锁 |
| MC 1.26.50 及以上 | 成就会被禁(预期行为,记录为平台限制而非缺陷) |

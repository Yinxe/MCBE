# 三叉戟绑定（trident throw + projectile claim）功能流程

> 一句话:让假人把身上的三叉戟逐把朝当前朝向投出，并可将飞行中的三叉戟/箭认主绑定给假人，使其归属（经验、忠诚回捡等引擎判定）落到指定主人或假人名下。

> 本文覆盖 scripts/ 中围绕三叉戟的两条相互衔接的主线：**假人投掷三叉戟**（一次性 UI 动作，串行投掷链）与**投掷物认主绑定**（双任归属模型，贯穿实体生成/加载/假人上下线的持续机制）。所有结论逐条与代码行为核对，只写文件路径 + 函数/常量名，不写行号。

## 0. 概念速览

| 术语                  | 指代                                                                                                                 | 位置                                                                                                            |
| --------------------- | -------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| 投掷链（throw chain） | 逐把把背包/热栏三叉戟移到主手、蓄力、释放的串行异步流程                                                              | `scripts/engine/TridentOps.ts` 的 `TridentOps.throwTridents()` / `runChain()` / `throwOne()`                    |
| 认主 / 绑定（claim）  | 给飞行/滞留的投射物实体打归属 tag 并重设引擎 `projectile.owner` 组件                                                 | `scripts/engine/ProjectileTracker.ts` 的 `ProjectileTracker`                                                    |
| 第一任（firstOwner）  | 实际投掷者，`mp:owner:<名>` tag，投掷瞬间打上、**不可变**（经验归属链的锚）                                          | `scripts/domain/ClaimRules.ts` 的 `makeOwnerTag()` / `claimOnSpawn()`                                           |
| 第二任（secondOwner） | 被绑定接管归属的假人，`mp:owner2:<名>` tag，**可被后续假人覆盖复写**                                                 | `scripts/domain/ClaimRules.ts` 的 `makeOwner2Tag()` / `ProjectileTracker.claim()`                               |
| 物品快照（itemTag）   | `mp:item:<附魔>                                                                                                      | <耐久>`——投射物实体没有可读物品组件，附魔/耐久只能在投掷瞬间记录                                                | `scripts/domain/ClaimRules.ts` 的 `encodeItemTag()`、`ProjectileTracker.encodeItemSnapshot()` |
| 家族（family）        | 主人 playerKey ∪ 主人名下全部假人名，认主扫描的"自家"判定集                                                          | `scripts/interface/Panels/Trident.ts` 的 `familyNamesOf()`、`scripts/domain/ClaimRules.ts` 的 `isFamilyOwned()` |
| 鱼钩标记              | 钓鱼浮漂经同一 `entitySpawn` 桥打 `mp:fisher:<名>`，是 `scripts/engine/Angler.ts` 钩真值探测的唯一索引（非认主体系） | `scripts/domain/ClaimRules.ts` 的 `makeFisherTag()`                                                             |

**绑定语义澄清（以代码为准）**：本能力**不是**工作模式（`domain/Catalog.ts` 无 trident 模式），也不读写忠诚/激流等附魔行为——它做两件事：① 让假人把手里的三叉戟逐把投出去；② 通过实体 tag + 重写 `minecraft:projectile` 组件的 `owner`，决定这些投掷物（含箭）在引擎层面"属于谁"。`projectile.owner` 是引擎判定投射物相关归属（经验等）的源头，代码注释称第一任为"经验归属链的锚"；忠诚回捡、激流推进等具体引擎行为由原版机制随 owner 生效，本模组不直接干预。追踪范围 `TRACKED_PROJECTILE_IDS = ["minecraft:thrown_trident", "minecraft:arrow"]`（药水箭 API 无法细分，一并按 arrow 计）。

## 1. 功能介绍

### 1.1 投三叉戟

让在线假人按勾选顺序逐把投掷背包/热栏/主手中的三叉戟。仅一把且就在主手时直接投掷不弹选择表单。投掷不扭头——保持假人当前朝向。

### 1.2 投掷物认主（绑定）

三叉戟/箭在以下时点自动维护归属，另有面板手动批量绑定：

- **投掷即标记**（自动）：任何投射物 `entitySpawn` 时，以 `projectile.owner` 解析出投掷者名字打第一任 tag，并把投掷瞬间的附魔/耐久快照打进 `mp:item:` tag。已有第一任即跳过（不可变，拾取再投不覆盖）。
- **加载 fallback**（自动）：区块重载触发 `entityLoad`，按"第二任在线 > 第一任在线 > 都不动"重设引擎 owner；双方都离线则不动，等上线夺回。
- **上线/重生夺回**（自动）：假人上线或重生时，扫描三维度中名下 tag 命中且"当前最优归属即自己"的投掷物，重设 owner 为自己（该判据防止抢走其他在线假人的第二任）。
- **下线回退**（自动）：假人下线时，仅把"第二任=自己"的投掷物回绑给在线的第一任（标签保留，等再夺回）；第一任=自己的不可变，无需切换。
- **UI 批量认主**（手动）：面板扫描假人半径 100 内（仅假人当前维度）家族名下投掷物，按 3 方块链式连通聚簇分组展示，勾选后该假人成为所选投掷物的第二任（覆盖旧第二任）。

tag 存于实体、跨重启保留；玩家用名字、假人用仲裁名作 tag 标识，不受 ADR-4 注册表键约束（`scripts/domain/ClaimRules.ts` 头注释）。

## 2. 入口与配置

```
/mp:trident <假人>            → showTridentSelector（投掷选择/快速直投）
假人面板 →「投三叉戟」按钮     → showTridentSelector
假人面板 →「投掷物认主」按钮   → showTridentClaimUI（扫描 + 分组勾选 + 批量认主）
```

- 命令注册：`scripts/interface/Commands.Ui.ts` 的 `UI_COMMANDS` 中 `mp:trident` 条目；命令仅是面板的一跳翻译，零业务规则。
- 面板按钮：`scripts/interface/Panels/BotPanel.ts` 面板构建函数中"投三叉戟""投掷物认主"两枚按钮，图标同为 `textures/ui/mockplayer/throw_trident`。
- 前置守卫：两个入口都先过 `scripts/interface/Kit.ts` 的 `ensureUiBotAvailable()`（要求假人在线且未死亡）；认主入口额外拒绝无主假人（`record.ownerKey === null` 时报"无主假人无法认主"）。
- **无 Config/模式开关字段**：`scripts/domain/Config.ts`、`scripts/application/Modes.ts`、`scripts/domain/Leases.ts` 均无三叉戟专属配置。全部可调参数是编译期常量：
  - `scripts/engine/TridentOps.ts`：`SETTLE_BEFORE_THROW = 2`（移位落定）、`CHARGE_TICKS = 20`（蓄力，注释"trident 15-20t"引擎实测下限）、`GAP_AFTER_RELEASE = 20`（释放后与下一把的间隔）。
  - `scripts/domain/TridentRules.ts`：`CLAIM_SCAN_RADIUS = 100`、`CLAIM_CLUSTER_RADIUS = 3`、`CLAIM_GROUP_PREFIX`（A=三叉戟、B=箭的组名前缀）。

## 3. 执行流程

### 3.1 投掷链（`scripts/engine/TridentOps.ts`）

**扫描** `scanTridents()`：主手三叉戟经 `minecraft:equippable` 组件判定；背包/热栏按 `selectedSlotIndex` 以下 36 格（`INVENTORY_SIZE`，`scripts/domain/Record.ts`）逐格 typeId 比对，**排除主手格防同一把重复计入**（`scripts/domain/TridentRules.ts` 的 `scanTridentSlots()`）。返回槽位 + 当下 `ItemStack` 引用，UI 层（`makeTridentLabel()`）渲染"主手/热栏 n/背包 n + 名称 + 附魔 + 耐久"。

**投掷** `throwTridents(botId, slots, opts)`，逐把串行，时序（tick）：

```
注册 pending 快照 ─→ 移位到主手(2t) ─→ useItemInSlot 按下 ─→ 蓄力 20t ─→ stopUsingItem 释放 ─→ 20t ─→ 回读主手格（仍持三叉戟=未投出）─→ 下一把
```

1. 互斥门：`throwing` Set 按 botId 互斥（A 投掷不阻塞 B）；已占用返回 `"already-throwing"`，假人不可用返回 `"not-online"`。
2. `runChain()` 开头快照 `savedMainhand`（链始主手物品）与 `mainhandSlot`；`finally` 统一执行主手恢复 `restoreMainhand()`；链返回实际投出把数。
3. 每把 `throwOne()`：槽位已空/换物即跳过（不算失败，继续下一把）；**投掷前**调 `projectileTracker.registerPending()` 注册附魔/耐久快照入队尾（entitySpawn 消费）；非主手把用"移动非交换"（源槽置 `undefined`，防双把同槽），主手原物暂存于链级快照、中途不回填。
4. 写 `selectedSlotIndex`（失败仍继续按下）→ `sleepTicks(2)` → `useItemInSlot()`（不扭头）→ `sleepTicks(20)` 蓄力 → `stopUsingItem()` → `sleepTicks(20)` → 回读主手格：仍持三叉戟即未投出。
5. 失败分支（每条先 `discardPending()` 撤回本快照，防旧附魔错配下一把）：移位后/蓄力后假人失效（死亡、下线）；`useItemInSlot` 抛错或返回 false；释放后回读主手仍持三叉戟——均判"未投出"，**本链立即中止剩余把**（下一把移位进主手会把失败件覆盖丢失），失败件留在主手待收尾回写。
6. 收尾 `restoreMainhand()` 先处置失败件：主手仍持三叉戟且源槽空且源位非主手格 → 失败件回写移位时清空的源槽并清主手，源槽被占则留在手不回写；随后**仅当主手格为空**（投出后正常离手）才回写链始快照——主手现持他链留下的件绝不覆盖该格（不再无条件清格/快照覆盖，玩家期间手动放置的物品不受影响）。从主手格本身投出的把不回写快照（`savedMainhand` 置空）。
7. 全程永不 reject（异步抛穿可崩游戏，注释纪律）；`finally` 中 `throwing.delete` + `inventoryChanged()` 报脏（SaveGate 增量落盘）。`ThrowResult` 为判别联合：`{status:"ok", thrown}`（携带实际投出把数）/ `already-throwing` / `not-online`；面板在 `thrown=0`（槽位全空或全部未投出）时播"未投出三叉戟"提示而非完成回执。

### 3.2 认主链路（`scripts/engine/ProjectileTracker.ts`）

事件入口由 `scripts/engine/Bridges.ts` 的 `onProjectileSpawn` / `onProjectileLoad` 订阅 `world.afterEvents`，先经 `isBridgeTrackedEntity()` 谓词降噪（entitySpawn 全局高频），只传 entityId，`scripts/main.ts` 装配处经 `entityGateway.rawEntity()` 回读实体后转 tracker——回调内同步、try-catch 隔离（F-18 纪律）。

- **spawn** `claimOnSpawn()`：已有第一任跳过；`projectile.owner` → `resolveOwnerName()`（反查表 `entityNames` → `Player.name`/`nameTag` → 实体 id 末兜底，空名也落 id——漏标=认主链断）→ 打第一任 tag；物品快照从 pending 队列**队尾**消费（`consumePending()`，LIFO、与 `discardPending()` 同端），队空回退读投掷者主手三叉戟（`readMainhandTag()`，玩家手动投掷路径）。
- **load** `onProjectileLoad()`：`parseOwnerTags()` 解出双任 → `resolveClaimOwner()`（`scripts/domain/ClaimRules.ts`：第二任在线 > 第一任在线 > undefined 不动）→ 重设 `proj.owner`，发 `via:"load"` 事件。
- **rebind** `rebind(botId)`：三维度（overworld/nether/the_end）按 owner/owner2 tag 查询命中实体，仅当 `resolveClaimOwner(...) === 自己` 才夺回，发 `via:"rebind"`。
- **release** `release(botId)`：仅"第二任=自己"的名下物，第一任在线才回绑并发生 `via:"offline-fallback"`；标签保留。
- **UI 认主** `claim(botId, entityIds)`：逐条校验受跟踪类型 → 读不到 `minecraft:projectile` 组件的整条按认主失败（不改 tag、不发事件、不计成功数）→ 先删全部旧 `mp:owner2:*` 再打当前 → 设 `proj.owner` → `claimed++` 并发 `via:"ui"`；面板回执"已认主 n/总数"并附失败件数。

### 3.3 认主面板与汇报

**扫描分组**（`scripts/interface/Panels/Trident.ts` 的 `showTridentClaimUI()`）：`scanOwnProjectiles()` 球形半径 100、仅假人当前维度、`isFamilyOwned` 过滤（组件缺失不剔除——附魔展示降级、认主必须可用）→ `buildClaimGroups()` 按 typeId 分桶后 `clusterPoints()` 单链接聚簇（距离 ≤3 即同组，传递连通），组间按规模降序、组内按 `neighborDensity()` 邻居密度降序，组 id 形如 `A01`/`B02`。条目行展示图标（🔱/🏹）、快照附魔（中文+罗马级，`scripts/domain/EnchantZh.ts`）、耐久、取整坐标、密度归一概率分档（≥60% 绿 / ≥30% 黄 / 其余蓝）与认主状态（✔已认主 / ⇄覆盖某第二任）。

**汇报**（`scripts/interface/ClaimReport.ts` 的 `dispatchClaimReport()`）：tracker 全部出口经 `scripts/engine/Hooks.ts` 的 `projectileClaimed()` → Composition 回挂 → 领域事件 `botProjectileClaimed`（`scripts/application/Events.ts` 声明负载）。派发矩阵：`via:"spawn"` 不汇报（投掷即标记不算认主变更）；`load/rebind/offline-fallback/ui` 按"目标假人→主人收认领 / 玩家第一任收被认走 / 旧第二任主人收顶替"分发，firstOwner 即主人时只发主人一路防重复计数；同 tick 按（接收玩家, 假人）聚合，`system.run` 汇总一条消息防刷屏。UI 路操作者经 `setClaimOperator()` 全局量排除（claim 事件同步发出，面板已有直接反馈）。

## 4. 停止与恢复

- **投掷互斥自动解除**：`throwTridents()` 的 `finally` 必达（永不 reject 纪律保证），`throwing` 集合即刻清账；异常/死亡/断链均走同一出口恢复主手。
- **跟随挂起**：`scripts/application/Capabilities/Follow.ts` 的 `FollowCap.tick()` 每拍先查 `tridentOps.isThrowing()`——投掷期挂起导航重发与距离判定，**关系与相位保留**，投掷链结束自动恢复节拍（假人投三叉戟不丢跟随）。
- **认主的断与续**：全部状态打在实体 tag 上，跨区块重载、跨世界重启存续。假人下线只是"第二任回退"，不是解绑——上线经 `rebind()` 夺回；重载经 `entityLoad` fallback 重设。双方都离线则引擎 owner 不动。
- **生命周期接线**（`scripts/Composition.ts` 尾段）：`botOnline`/`botRespawn` → `trackOnline()` + `rebind()`；`botOffline` → `untrackBot()`（按名清反查表，名字是唯一稳态）+ `release()`。引擎自发重连（非我方管线的实体替换）在 `scripts/application/Lifecycle.ts` 的 `restoreRejoined()` 里对账 `trackOffline(旧id)`/`trackOnline(新id)`。
- **取消令牌**：`ThrowOptions` 现仅剩 `token`（`scripts/domain/Cancellation.ts` 的 `CancelToken`，等待节点提前结束、把与把之间检查取消状态退出），但当前两个 UI 入口均未传入——投掷链一经启动即跑到自然结束或中止，无用户侧中断入口。

## 6. 已知限制与引擎约束

- 认主 UI 扫描**仅假人当前维度**（半径 100）；rebind/release/load 才覆盖三维度。跨维投掷物需在对应维度的假人操作 UI 认主。
- 投射物实体无可读物品组件（引擎事实）：附魔/耐久只能投掷瞬间快照进 `mp:item:` tag；快照读不到不拦认主，仅展示降级。
- 箭与药水箭无法细分（`TRACKED_PROJECTILE_IDS` 注释），一并归 arrow 组。
- 蓄力 20t、间隔 2t/20t 为引擎实测节奏下限（`TridentOps.ts` 头注释），不可随意压缩。
- `pending` 快照队列以**名字**为键、队尾注册、队尾消费与撤回（LIFO）；串行投掷保证与 entitySpawn 一一对应。名字仲裁（F-03）之外的同名竞态未做额外防护。
- 投掷链一旦某把未投出即中止剩余勾选，不回退重试、不跳过续投——剩余把需重新勾选再发起下一次链。
- 第一任不可变是硬约束：拾取再投、UI 认主都只动第二任；重设的是引擎 `proj.owner`，`mp:owner2:` 标签与引擎 owner 在 load/rebind 路线上可以不同步（设计上标签是账本、owner 是当前代理）。
- 投掷不扭头：假人朝当前朝向投出，方向控制不在本能力范围。
- 鱼钩（`minecraft:fishing_hook`）不在认主体系内，只有 `mp:fisher:` 单主标记。
- 认主事件对真人第一任只按名字汇报，`ClaimInfo.botId` 为 undefined（`scripts/engine/Hooks.ts` 注释口径）。

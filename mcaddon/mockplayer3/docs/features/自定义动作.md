# 自定义动作（custom）功能介绍与流程

> 一句话：玩家给假人写一段**动作表**（走到 / 等待 / 挖掘 / 放置 / 使用物品 / 攻击 / 说话 / 看向 / 潜行 / 跳 / 跳转），假人按顺序执行，可整段循环、可中途改动作表即时生效、单条失败可选择停下或跳过。
> 参考旧版：`archive/mock-player`（3.1.6 起，`rules/script/ScriptRules.ts` + `features/ai/capabilities/script.ts` + `interaction/{commands,ui}/…/script.ts`，约 1830 行）。本文只述 v3 重写后的实现。

## 0. 相对旧版的取舍（本次重设计）

| 面         | 旧版（3.1.6）                                                                   | v3 现在                                                                                            |
| ---------- | ------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| 运行状态   | `record.scriptRunning` 标记 + `workMode` 双条件才跑（`/mp:work script` 不生效） | **只有一个真源**：`workMode === "script"` 就跑，无额外标记字段                                     |
| 重跑信号   | `kicks` 计数 + 协程每轮轮询比对；内容指纹比 JSON                                | **版本号**（`ActionLibrary`）：任何写入 +1，执行器在**动作边界**看到就换新动作表重开（不必等整轮） |
| 动作表存档 | 塞在整条 `BotRecord` 里（与位置/标签/经验共用一个 DP 键，256 条是保险）         | 独立键 `mp:action:<botId>`；写入带体积护栏（24KB 估算上限）并回中文原因，不触发 DP 超限抛穿        |
| 执行逻辑   | 循环/跳转/死循环护栏与异步执行器缠在一起，只能整机冒烟                          | **游标抽成纯状态机**（`domain/ActionCursor`）：顺序/循环/跳转/死循环护栏可离线单测                 |
| 面板       | 4 层（主页→分类→动作类型→参数），6 条/页，改一条要重填全部字段，删除无确认      | **整段文本编辑是主路径**（一条一行或 `                                                             | ` 分隔）+ 追加/按序号删除（带确认）+ 循环自填；无多级页签 |
| 循环设置   | 只有 1 / 3 / 10 / 一直 四个预设                                                 | 文本填「一直 / 一次 / N」（上限 9999）                                                             |
| 失败策略   | 只有"停下"                                                                      | 新增 `onFail`：停下并报告 / 跳过该条继续                                                           |
| 长距离走位 | 分 `navigateBot`（≤16）与 `longNavigateBot` 两条路                              | `mover.navigateFar`：一条 API 内自动分段（每段 12 格，最多 64 段），失败原因统一                   |
| 用物/放置  | 各自的 `useItemOnce` / `placeBlockOnce` 端口                                    | 复用现成原子：`panelOps.useItemOnce`（吃/用一体）、新增 `placer.placeAt`（按坐标放，动作表需要）   |
| 说话/跳    | 直接调实体方法                                                                  | 收敛为 engine 原子 `ops.say` / `ops.jump`（entity 侧唯一出口）                                     |
| 注释/备注  | `note` 字段（列表显示）                                                         | 保留（≤100 字）；**文本编辑不保留备注**（面板已注明）                                              |
| 事件解耦   | 只有入口走 UI 事件，其余面板直接改 record 并落盘（命令与界面两套实现）          | 面板与命令**都只调 `ActionLibrary`**（读/写/重跑/状态同源），不再各自解释动作表                    |

## 1. 模型（`domain/ActionRules.ts`）

一段动作表 = 动作序列 + 整段循环 + 失败策略：

```ts
{ steps: ActionStep[]; loopCount: number; onFail: "stop" | "skip" }
```

12 种动作（`note?` 备注所有类型通用）：

| 动作       | 参数       | 说明                                                        |
| ---------- | ---------- | ----------------------------------------------------------- |
| `moveTo`   | x y z      | 走到坐标（>16 格自动分段，最多 64 段≈768 格）               |
| `wait`     | ticks      | 等待（上限 1 小时）                                         |
| `mine`     | x y z      | 挖指定格（≤6 格；自动按方块选最优工具；技术方块由白名单挡） |
| `mineLook` | look?      | 挖准星前方第一格；给 look 就先转向                          |
| `place`    | x y z      | 往指定格放主手方块（≤6 格，六邻需实心支撑）                 |
| `useItem`  | look?      | 使用主手物品一次（吃/用一体）                               |
| `attack`   | count      | 挥击 N 次（上限 500，每 4t 一次）                           |
| `say`      | text       | 全服说话（≤200 字，前摇 10t）                               |
| `look`     | x y z      | 转向坐标（连续注视，保持到下次转向）                        |
| `sneak`    | on + look? | 潜行开/关（运行期姿态，不写记录开关）                       |
| `hop`      | look?      | 跳一下                                                      |
| `jump`     | target     | 跳转到第 N 条（向后＝跳过，向前＝自定义循环）               |

上限（防误填拖死服务器）：动作 ≤256（`MAX_ACTIONS`）、等待 ≤1h、攻击 ≤500、说话 ≤200 字、循环 ≤9999、坐标 |v| ≤3e7。

## 2. 文本规格（命令与面板共用同一解析器）

- 关键词（中英等价）：`走到/移动到`、`等待`、`挖掘`、`挖前方`、`放置`、`使用物品`、`攻击`、`说话`、`看/看向`、`潜行开`、`潜行关`、`跳一下`、`跳转`。
- 支持连写与括号坐标：`走到100 64 200`、`走到 (10,64,20)`、`走到 10,64,20`；坐标一律向下取整。
- 整段用 `|` 或换行分隔；`parseActionsSpec` 逐条解析并**指出第几条错在哪**（一条错不丢整段）。
- `export` 把动作表按**一条一行**发到聊天栏，可直接整段粘贴回 `set`（备份/搬运用）。
- **坐标缺省**：坐标类动作（走到 / 挖掘 / 放置 / 看）在面板与命令里不写坐标＝用**操作者当前所在格**
  （`parseActionSpec` 的 `defaults` 注入，纯逻辑层不碰世界）；可空坐标的动作（挖前方 / 使用物品 / 跳一下 /
  潜行）留空仍是无坐标语义，不受兜底影响。面板的追加表单与命令 `add`/`set` 同一口径。
- 写回与面板预览用**一条一行**（`actionsToSpecLines`），与 `parseActionsSpec` 互为逆运算；日志/回执用单行
  `|` 分隔（`actionsToSpecText`）。
- 与写回互逆：`actionsToSpecText` ↔ `parseActionsSpec`（单测锁往返一致）。

## 3. 执行（`domain/ActionCursor` + `application/Capabilities/CustomAction.ts`）

- **游标**（纯状态机）：`peek()` 消化 `jump` 与整段循环后停在待执行条，`commit()`/`skip()` 推进一步；跳转越界与"连续跳转 >40 次"判死循环并回中文原因。
- **常驻协程**（能力 `start` 起跑，`stop` 取消）：外层等"有动作表且版本号变过"，内层按游标逐条执行；**每条之间 1t 节拍**，等待/走位/破坏都是 `await`（业务节拍与游戏刻无关）。
- **中途改动作表即时生效**：写入即版本 +1，执行器在下一个动作边界发现版本变化 → 丢掉旧游标、用新动作表从第 1 条重开（旧版要等整轮跑完）。
- **失败语义**：`onFail=stop` → 状态记 failed + 私信主人（含"改好后再运行"）+ 保留模式待命；`onFail=skip` → 落日志跳过该条继续。**模式不自动切换**：停不停由玩家决定（面板/命令）。
- **看门狗** `Capability.tick`（20t）：续 `hands`/`motion` 租约 + 存活检查；破坏逐格租约由 `breaker` 自持自续（与定点挖掘同口径）。注视走 `gaze.forceLook` 一次性锚定，停机 `gaze.stopHold` 中性化。
- **停机现场**：取消令牌 → `mover.stop`（在途走位作废）+ `stopSwing` + `gaze.stopHold`，状态回落 idle。

## 4. 存档与状态

- 动作表存独立 DP 键 `mp:action:<botId>`（`engine/ActionStore`）：读回一律过 `normalizeActions`（坏条目丢弃、超上限截断），空动作表删键；写入前按 UTF-8 最坏 3 字节/字符估算，超过 24KB 回中文原因。
- 运行状态（阶段/当前条/轮次/失败原因）在 `domain/ActionStatus` 的状态板里，**仅进程内存活**；删假人时 `ActionLibrary.forget` 一并清动作表、版本号与状态（旧版漏了这步，内存里会残留）。
- 动作表不进 `BotRecord`：档案每次对账整条读写，动作表只在编辑/运行时才需要，且可达 256 条。

## 5. 入口与权限

| 入口                                    | 条件                                     | 落点                                           |
| --------------------------------------- | ---------------------------------------- | ---------------------------------------------- |
| 命令 `/mp:action <假人> [动作] [参数…]` | 主人或管理员（`ctx.bot` 统一执法）       | 无动作＝打开自定义动作面板并回状态；其余见下表 |
| 假人面板 →「自定义动作」按钮            | 主人或管理员（面板自带 `guardUiManage`） | 自定义动作面板                                 |

命令动作：`panel`（默认）/ `list` / `add <规格>` / `set <整段规格>` / `del <序号>` / `dup <序号>` / `move <序号> <上|下>` / `loop <一直|一次|N>` / `fail <停|跳过>` / `clear` / `export` / `run` / `stop` / `status` / `help`（另有中文别名：添加/列表/清空/循环/运行/停止/状态/帮助）。
参数只有单 token 类型，故命令最多拼 6 段文本；**长动作（说话/备注）用面板改**。

面板（ActionForm + ModalForm，全部就地重开）：

```
自定义动作面板（状态 + 条数 + 循环 + 失败策略 + 前 8 条预览）
├ ▶ 运行动作表 / ■ 停止动作表      （= changeWorkMode custom / none + requestRerun）
├ ✎ 编辑动作表（整段文本）        → Modal：先只读预览（一条动作一行，超 20 行只报条数）
│                                 再接整段输入框（一条一行）+ 循环 + 失败策略（逐条报错，有错整段不保存）
├ ＋ 追加一个动作              → Modal：动作类型下拉（13 项）+ 参数 + 备注（坐标留空＝你当前站位）
├ ⇅ 整理某个动作              → Modal：下拉选动作（列到 40 个）+ 下拉选操作（改参数 / 复制一份 / 上移 /
│                                 下移 / 删除）；选「改参数」再开一层：类型可换、参数与备注预填
├ 🗑 清空动作                  → Modal：toggle 确认
└ （返回 = 关闭表单）
```

## 6. 已知限制

- 「使用物品」一步不可中断：吃/用最长约 4 秒（引擎原子无取消口），停机要等它结束。
- 文本编辑不保留 `note` 备注（列表/面板里能看到，改文本即丢）。
- 潜行是运行期姿态：不写 `record.switches.sneaking`，重连/重生后按记录开关恢复（动作表不会改玩家设置）。
- `place` 走引擎原生 `useItemInSlotOnBlock`：目标格非空或六邻无实心支撑即失败；不自建支撑、不垫脚。
- 动作表没有条件与变量（`jump` 只有无条件跳转）；要分支请在动作表外解决或等后续版本。

## 7. 测试与验收

离线（`pnpm run test:core`，327 通过）：

- `tests/domain.ActionRules.test.ts`：动作类型目录自洽、13 个动作类型文本解析（含连写/逗号坐标/可空坐标）、拒绝表（未知动作类型/越界/超限全回中文原因）、整段规格逐条报错、文本↔动作表往返一致、存档归一化、循环与失败策略出入口、中文描述、面板参数互转。
- `tests/domain.ActionCursor.test.ts`：顺序执行、循环 N 次与一直循环、跳转（向前跳过/向后自定义循环）、跳转越界与互相指认的死循环护栏、空动作表、skip 语义。

实机验收（管理员先在「实现性功能」总闸里打开本模式）：

1. `/mp:action <假人> set 走到 <坐标> | 等待 2 | 挖前方` → `run` → 面板状态显示逐条推进。
2. 面板「编辑动作表」改成 `走到 … | 放置 … | 说话 你好` → 运行中保存 → 立刻用新动作表从第 1 条重跑。
3. 故意写一条够不着的 `挖掘`：`onFail=stop` 时停下并私信主人（附第几条与原因）；改成「跳过该条」后能继续跑完。
4. `跳转 1` 单条自环 → 连续跳转护栏把它按死循环停下（不刷屏、不卡服）。
5. 切模式/下线 → 走位、挥拍、视角都停住（租约由 `stopCurrent` 统一撤）；重新上线按 `workMode` 自动接着跑。
6. 写 200+ 条动作表（含长备注）看是否触发体积护栏并给中文提示。

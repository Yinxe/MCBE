# 定点放置（place）功能流程

> 一句话:假人原地不动、不转向，按固定节拍把主手方块连续放置到准星命中的面前位置，用于自动砌墙、铺地。

> 假人常驻节拍把主手方块放到正前方的机械重复能力。文中 `文件 · 符号` 标注均对应 `scripts/` 下当前实现，逐条与代码行为核对（基线：分支 `feat/mock-player-rewrite`）。设计出处：`docs/mockplayer/03-详细设计/04-能力体系与调度.md` §3.2（FR-W4，规格修订 2026-09-27：回归归档"放面前"机械模型）；与归档差异见 `docs/mockplayer/11-归档源码对齐差异审查.md`（"旧无主手校验永不停机 → 新启动即拒非方块主手；LAY 单相位节拍"）。

## 1. 功能介绍

**做什么**：假人原地不动、视角零改动，按固定节拍（2 tick/块）把**主手**方块放置到**准星命中面外侧的目标格**上——放置靶格完全由玩家预设的朝向/准星决定（与定点攻击同口径，`Place.ts` 头注）。典型用法：主人把假人摆好朝向、对准支撑面，让它持续砌墙/铺地/补方块（常规支撑走 `startBuild`，引擎按放置规则落块并自动扣料）；对准箱子/门/按钮等**可交互支撑**时改走相邻空格直写，方块落在其外侧格而**绝不打界面**（`startBuild` 对这类面会被方块自身交互吃掉，而 `playerInteractWithBlock.cancel` 与潜行对 SimulatedPlayer 的界面开启都拦不住）。

**前置条件**（启动即拒的只有第一条，其余为"天然空转"语义）：

1. **主手必须是可放置方块**：`placer.mainhandKind` 读 `minecraft:equippable` 主手件 typeId，与 `MinecraftBlockTypes` 全表同名才判 `block`，同名特殊件另列拒启清单（门/活板门/按钮按后缀覆盖全系材质，床/杠杆为同名特例，`engine/Placer.ts` 的 `BLOCK_TYPE_IDS`/`NON_PLACEABLE_SUFFIXES`/`NON_PLACEABLE_EXACT` 常量与 `mainhandKind()`）；启动时判为 `empty`/`not-block` → `start` 返回中文原因拒绝（`PlaceCap.start()`）；判为 `offline`（实体/主手组件暂不可读的瞬态，含组件读取抛错）**不拒启**——照常进 LAY 低频重探，就绪自动恢复。
2. **准星 6 格内有命中面**（`Place.ts` 的 `REACH` 常量=6，与破坏原子同口径 `Placer.ts` 的 `DEFAULT_MAX_DISTANCE`）——无目标时不报错，低息重探等主人摆好角度。
3. **前方有落块空间**——不检测：引擎静默拒放时按 `unchanged` 照拍重试（`PlaceCap.tick()` 的 default 分支）。
4. **主手持续有货**——不自动从背包取料：掏空后每拍起手重读主手判为非方块，不发起放置、10t 低息重探；主人手动补进主手即自动恢复连放（`Place.ts` 头注、`tick()` 的主手判定段）。

**不是什么**：没有范围/图案/选点（单点机械放置，D-06 域扫描/AIM 自证对本模式已撤销，设计 §3.2）；不会移动、转向、注视；不会挖掉挡在前面的方块。

## 2. 启用与配置入口

```
/mp:work <假人名> place            ──→ lifecycle.changeWorkMode(viewer, botId, "place")
假人面板 →「行为菜单」→ 工作模式下拉选「定点放置」 ──→ 同上
```

- **命令**：`interface/Commands.Behavior.ts` 的 `BEHAVIOR_COMMANDS` 表 `mp:work` 条目。参数 `mode` 为引擎 Enum（值表由 `WORK_MODES` 目录 id 派生，故命令行只吃 `place` 这个 id）；`mp:work <假人> list` 渲染目录含当前模式与 `[已禁用]` 标注（`execute()` 的 list 分支）。别名表 `modeAliasMap`（中文"定点放置"→`place`，`domain/Catalog.ts` 的 `modeAliasMap()`）供面板/内部路径收窄使用。
- **面板**：假人管理面板「行为菜单」按钮（`interface/Panels/BotPanel.ts` 的 `showBotPanel()`）→ `interface/Panels/Behavior.ts` 的 `showBehaviorPanel()`：工作模式单选下拉（`workMode` dropdown），选项按 `config.workModeEnabled` 过滤（`options` 过滤段），**节拍配置不入面板**（头注）；提交走 `changeWorkMode`（提交段）。
- **管理员总闸**：全局配置面板"▣ 定点放置"开关（`interface/Panels/Admin.ts` 的 `MODE_META` 表 place 条目与 `showGlobalConfig()` toggle 循环）写 `config.workModeEnabled.place`（`domain/Config.ts` 的 `GlobalConfig.workModeEnabled` 字段）。**place 默认启用**（`domain/Catalog.ts` 的 `defaultEnabledModes()` 默认表全模式开）。禁用后切换请求被拒："该模式已被管理员禁用"（`Modes.change()` 的禁用闸），已在运行的不受影响。
- **离线预置**：假人不在线时切换只写穿记录 `workMode=place`（`Modes.change()` 的离线预置支，日志"模式预置…下次上线生效"），下次上线/自动重生尾段 `attachAfterRestore` 回挂（`Lifecycle.online()`/`Lifecycle.respawnTail()` 回挂点）；回挂失败会私信发起者/主人"模式恢复失败…已回到空闲"（`online()`/`respawnTail()` 的失败通报段）。主手非方块的假人离线预置后，上线回挂即因 `start` 拒而落空闲并播报原因。
- **旧档迁移**：归档标签 `autoPlace` 折为 `workMode=place`（`domain/Migrate.ts` 的 `LEGACY_TAG_MODE` 映射表）。
- **帮助文本**：`interface/Panels/HelpGuide.ts` 的 `SECTIONS` 表（"将手中方块放置到面前位置"）、目录 help "持续把主手方块放置到正前方（主手非方块拒绝启动）"（`domain/Catalog.ts` 的 `WORK_MODES` 表 `place` 条目）。

## 3. 启动序列（Modes 五道闸，`application/Modes.ts` 的 `change()`）

```
changeWorkMode(viewer, botId, "place")（Lifecycle.changeWorkMode()）
 ├─ 记录不存在 → "假人不存在"
 ├─ canManage 不过 → "只有主人或管理员可修改该假人"（命令侧 resolveBot 已先校验一道）
 └─ Modes.change(botId, "place", now)
     ├─ ① workModeEnabled.place=false → 拒 "该模式已被管理员禁用"
     ├─ ② 无会话 → 离线预置支（写穿记录即成功）
     ├─ ③ 会话态非 ACTIVE/WORKING → 拒 "当前状态不可切换模式"
     ├─ 幂等：已是 place 且能力挂位 → 直接 ok
     ├─ stopCurrent 停旧能力（撤租约+卸上下文）
     ├─ ④ 租约预取：requires=[{kind:"hands"}]，HOLD/TTL100；
     │      被占 → 撤预取、拒 "所需资源被占用（持有者：…）"
     ├─ 建上下文 {mode:"place", phase:{name:"INIT"}, data:{}}（D-01：
     │      能力零实例态）
     ├─ ⑤ PlaceCap.start：主手判定
     │      ├─ not-block → 拒 "主手不是可放置方块"
     │      ├─ empty     → 拒 "主手没有物品"
     │      ├─ offline   → **不拒绝**（实体/组件暂不可读的瞬态；拒启会把用户
     │      │              持久模式写穿为 none）——同 block 分支起跑，交 tick
     │      │              低频重探，就绪自动恢复
     │      └─ block     → ctxOf 建 data["place"]={base:null}，
     │                     phase = { name:"LAY", nextWakeAt: now+PLACE_SETTLE_TICKS(8) }
     │                     成功
     │      （start 被拒一律落空闲：撤租约、卸上下文、workMode 写穿 none、
     │        原因回显 + 游戏日志，change() 的 start 拒绝分支与 dropToIdle()）
     └─ 成功：transitTo("startWork") → WORKING、workMode 写穿保存、
        console.warn 模式切换日志、emit botWorkModeChanged
```

设计理由（`PlaceCap.start()` 注释）：主手**确认**非方块/空手时显式失败好过无声空转，拒绝原因由 Modes 透传给主人；`offline`（含组件读取抛错，`Placer.mainhandKind()` 的 try-catch 口径）是瞬态，拒绝会把用户持久设置清掉，故放行等恢复。`PLACE_SETTLE_TICKS=8` 首拍缓冲：生成窗引擎逐 tick 锁回旋转（F-01），先缓冲再按视角放置。

## 4. 执行流程：LAY 单相位节拍循环

调度器只在 `state===WORKING && now >= capability.phase.nextWakeAt` 时回调 `tick`（`application/Scheduler.ts` 的 `runSession()`），每拍全流程同步、无 await（F-18/D-05）：

```
每拍 tick(session, now)（PlaceCap.tick()）
 ├─ 相位守卫：capability 缺失或 phase.name!=="LAY" → 直接返回
 ├─ hands 租约续租 TTL=100t（视角零改动，不发任何注视）
 ├─ loc = mover.locationOf(botId)：读不到（实体/位置瞬态）→ 10t 低息重探返回
 ├─ 漂移守卫（ctx.base，data["place"] 私有上下文）：
 │    首拍（已过 8t 启动缓冲）记录 ctx.base=脚下格；
 │    之后 distance3d(脚下格, base) > DRIFT_LIMIT(1) → 10t 排拍 +
 │    host.autoStop("脚下位置漂移，已停止放置")——防主手方块在脚下自叠塔
 │    失控升高，经 Composition capHost 私信主人 + modes.change("none")
 ├─ kind = placer.mainhandKind(botId)：非 "block"（空手/非方块/组件瞬态）→
 │    **跳过发起**（不进 placeInFront）+ 10t 低息重探——
 │    空手/非方块无可写目标（既不能 build 也无方块可直写），故跳过
 └─ result = placer.placeInFront(botId, REACH=6)
      └─ Placer.placeInFront（engine/Placer.ts 的 placeInFront()）：
          1. botOf/botValid 解析实体，不可达 → "offline"（Atomic.ts 的 botOf()/botValid()）
          2. hit = bot.getBlockFromViewDirection({maxDistance:6})；无命中 → "no-target"
          3. 主手非可放置方块（空/非 BLOCK_TYPE_IDS/同名特殊件）→ "unchanged"
          4. bot.stopBreakingBlock()（打断进行中挖掘；无挖掘态可能抛，忽略继续）
          ├─ 支撑面可交互（isInteractableSupport：沿用误点拦截名单判定 GUI/容器 + 门/活板门/按钮后缀 + 拉杆）
          │  → 特殊通道 placeAgainstInteractable：
          │    a. 目标格 = floor(支撑格) + FACE_NORMALS[命中面]；命中面非法 → "no-target"
          │    b. 读目标格现状：非空（isAir=false，含越界不可读）→ "unchanged"（绝不覆盖既有方块）
          │    c. dim.setBlockType(目标格, 主手方块 typeId) → 回读目标格 typeId 相符才 "placed"
          │       （不发起任何右键/交互 API；这类面 startBuild 会被方块自身吃掉＝开界面/开关）
          │    d. 成功后 consumeMainhand 手动扣 1（背包/equippable 瞬态则本次不扣，下拍照放）
          │    e. 维度/区块读写抛错 → "offline"
          └─ 常规支撑 → 常规通道 placeByBuild：
               a. before = floor(支撑格)
               b. bot.startBuild(手持槽) → bot.stopBuild()（引擎按规则落一块并自动扣料；抛错→"unchanged"）
               c. after = rayHit(bot, 6)：无命中或 after==before → "unchanged"；他格 → "placed"（D-04 射线差分）
 └─ 按结果定下一拍（setPhase，Place.ts 的模块级 setPhase()）：
      placed / unchanged → nextWakeAt = now + PLACE_INTERVAL_TICKS(2)（tick() default 分支；MineRules.ts 的 PLACE_INTERVAL_TICKS 常量）
      no-target / offline → nextWakeAt = now + IDLE_RECHECK_TICKS(10)（tick() 低息分支；MineRules.ts 的 IDLE_RECHECK_TICKS 常量）
```

**照拍重试、除漂移外不停机**是规格（`Place.ts` 头注）：`unchanged`＝目标格非空或落块回读未达（前方无落块空间），照 2t 连放节拍重试；`no-target`/`offline`/空手/非方块＝瞬态或空转，10t 低息重探等补货/等会话恢复，**不发起**。唯一自动停机出口是脚下位置漂移守卫的 `autoStop`（经 `CapabilityHost` 注入，`Composition.ts` 的 `capHost` 与 `modes.register(new PlaceCap(capHost))`）。节拍常量**写死不入配置**（`domain/MineRules.ts` 节拍常量段注释：挖掘/放置 2、攻击 8，各假人独立相位机互不干扰）。

## 5. 停止与结束条件

| 场景                                             | 行为                                                                                                                                | 出处                                                                                   |
| ------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 手动切走（`mp:work <假人> none/其他`、面板改选） | `stopCurrent` 卸能力、撤 hands 租约（无 gaze HOLD 需中性化）；place 的 `stop` 为空——放置是同步瞬时调用，无在途可取消                | `Modes.change()` 调用 `stopCurrent()`、`PlaceCap.stop()`                               |
| 下线/删除/死亡管线                               | 三管线共用 `stopCurrent`（幂等），租约必撤                                                                                          | `Modes.stopCurrent()` 文档注                                                           |
| tick 抛穿                                        | Scheduler 捕获：console.error + `stopCurrent` + `workMode=none` 写穿保存（仅停该假人，不牵连同 tick 其余会话）                      | `Scheduler.runSession()` 的 tick try-catch 分支                                        |
| 材料耗尽（主手掏空）                             | **不停止不报错**：每拍起手读主手判为 `empty`/`not-block` 即不发起，10t 低息重探，补货即恢复                                         | `tick()` 的主手判定段                                                                  |
| 准星无目标/条件不满足                            | **不停止**：10t 低息重探，等主人摆角度/清空间                                                                                       | `tick()` 的 no-target/offline 分支                                                     |
| 脚下位置漂移（与首拍基准偏差 >1 格）             | **autoStop 落空闲**：`host.autoStop("脚下位置漂移，已停止放置")`——私信主人 + `modes.change("none")`；防主手方块在脚下自叠塔失控升高 | `tick()` 的漂移守卫分支、`Composition.ts` 的 `capHost`                                 |
| hands 租约被抢                                   | place 运行期每拍续租（TTL 100t），同会话内互斥模式已被"切模式先停旧"保证；异主抢占在 Modes 预取闸发生（启动时 EBUSY 即拒）          | `tick()` 续租段、`Modes.change()` 租约预取循环、`Leases.ts` 的 `renew()` 与 `expire()` |
| 管理员禁用 place                                 | 只拦**新的**切换请求（"该模式已被管理员禁用"），运行中的不受影响                                                                    | `Modes.change()` 的禁用闸                                                              |

自动停机出口只有漂移守卫一处（`CapabilityHost.autoStop` 缝经 `Composition.ts` 注入：`modes.register(new PlaceCap(capHost))`）；其余失败语义一律照拍/低息重试，对比挖掘/攻击连该出口都没有。

## 6. 与其他子系统的交互

- **注视/租约（gaze）**：零交互。`requires()` 只声明 `hands`（`PlaceCap.requires()`），每拍不发注视——这是与归档"放置会拧视角"事故的结构性了断（F-06 租约化在 place 侧的直接收益：连租约都不欠）。
- **导航/移动（motion）**：零交互。不申请 motion 租约、不调 Mover，假人摆放位置与朝向全归主人。
- **误点守护（ClickGuard）**：常规支撑 `startBuild` 命中非交互面不弹界面，且常规支撑不在拦截名单内（`judgeBlockClick` 判不拦），无需 `grant`；可交互支撑改走 `setBlockType` 相邻空格直写，**根本不发起右键/交互 API**，也就没有 `playerInteractWithBlock` 可拦。两通道都不依赖 `grant`——因为对 SimulatedPlayer，`playerInteractWithBlock.cancel` 与潜行标志都拦不住自家开界面，可靠做法是常规面用引擎放置、可交互面绕开交互。ClickGuard 现只服务于面板"前方交互"与宝库开箱等**必须右键**的有意交互。
- **破坏态**：发起前 `stopBreakingBlock()` 打断进行中的挖掘（`placeInFront()` 的打断调用与 `Placer.ts` 头注，挖掘态下放置冲突的引擎事实）；但 place **不持有 breaking 租约**，与定点挖掘的按格 breaking 账本无涉。
- **背包/主手**：只读判定（`mainhandKind` 经 equippable 组件，`Placer.mainhandKind()`），从不写背包——补货由主人经主手面板/物品交换等途径完成后，下一拍自然恢复。主手消耗量的持久化走下线/死亡管线的全量对账（`exportItems` 快照落仓，见《资源回收》§3/§7），放置过程本身无逐块落盘。
- **保存门控（SaveGate）**：切换成功/落空闲时 `workMode` 写穿 `saveRecord`（`Modes.change()` 各写穿点）；受 SaveGate epoch 规则约束——假人生成后恢复提交（epoch≥1）前一切物品写被挡（F-26/ADR-5），模式回挂发生在 epoch 提交之后（`Lifecycle.online()` 的 epoch 提交段）。
- **调度（Scheduler）与时钟**：单一 `nextWakeAt` 时钟驱动（D-05），逐会话异常隔离（F-18）；租约 TTL 过期撤销由调度器每拍先清（`runSession()` 的 `leases.expire` 段）。
- **日志/播报**：无逐次放置播报（静默机械循环）；可见面为模式切换 `console.warn`（`Modes.change()` 成功日志）、切换被拒日志（`Modes.refuse()`）、命令/面板的一次性回执（`mp:work` 的 `execute()` 回执段）、上线回挂失败的私信（`Lifecycle.online()` 失败通报段）。`botWorkModeChanged` 事件已发射（`change()` 各 emit 点）。

## 7. 已知限制与引擎约束（台账）

- **方块判定保守**：item typeId 与方块 id **同名**才视为方块候选，且同名特殊件另列拒启清单——门/活板门/按钮按 `_door`/`_trapdoor`/`_button` 后缀覆盖全系材质，床/杠杆为同名特例（`engine/Placer.ts` 的 `NON_PLACEABLE_SUFFIXES`/`NON_PLACEABLE_EXACT` 常量与 `isNonPlaceableSpecial()`），判 `not-block` 拒启/不发起；组件读取抛错按 `offline` 瞬态处理（启动不拒、运行低息重探），此类方块请改用其他方式。
- **双通道、绝不顶掉既有方块**：常规支撑交引擎 `startBuild`（目标被占/规则不满足即放不下，天然不覆盖、不凭空产块，扣料由引擎原子完成）；可交互支撑改 `setBlockType` 直写，但**只向 `isAir` 的目标格写**——目标非空（含越界不可读）一律判 `unchanged`，不会把支撑面外侧原有的方块/物品顶掉。手动扣 1 在回读确认落块之后；扣料遇背包/equippable 瞬态则本次不扣（宁少扣一次，也不凭空多放），下拍照重放。
- **靶面=准星预设**：6 格射线内无命中即 `no-target` 低息重探；引擎静默拒（空间被占/支撑面不合法）无从区分，统一按 `unchanged` 重试，**不会**上报"为什么放不下"。
- **无自动取料/补货**：主手掏空后不发起、10t 低息重探直到人工补货——空手/非方块主手无可写目标，必须跳过（`Place.ts` 头注）。
- **节拍与缓冲不可配**：`PLACE_INTERVAL_TICKS=2`、`IDLE_RECHECK_TICKS=10` 为 domain 常量（`MineRules.ts` 的节拍常量段），`PLACE_SETTLE_TICKS=8`（首拍缓冲）与 `DRIFT_LIMIT=1`（漂移硬闸）为 `Place.ts` 模块常量；旧版"动作速度（tick）"字段未入新配置（`Panels/Behavior.ts` 头注 "节拍配置不入面板"）。
- 引用的纪律编号：F-06（注视租约化——place 零注视侧证）、F-18（tick 同步短小无自旋）、F-25（方块坐标一律 floor）、D-01（能力零实例态，相位即全部状态）、D-02（租约冲突即拒）、D-04（后置条件回读——常规通道射线差分、特殊通道目标格 typeId 相符才算 placed）、D-05（单一时钟 nextWakeAt）。
